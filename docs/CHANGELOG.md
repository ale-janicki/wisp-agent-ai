# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Entries are in descending chronological order (newest first).

## [Unreleased]

### Added

- Brain search for every engine: `wisp mcp brain` is an MCP server (`wisp-brain`) with three read-only tools. `brain_search(query, limit)` ranks notes by title, aliases, headings and text (BM25) with a boost from the wikilink graph; `brain_read(path_or_title)` opens a note by name, alias, path or `[[wikilink]]` (`#heading` and `|text` work) and returns it with its outgoing links and backlinks; `brain_links(note, depth)` walks the link graph. The index is a local SQLite file in the Wisp state folder that updates itself when files change; nothing leaves the Mac. `wisp setup harness` registers it in Claude and in the Codex config; the local engine has it built in.
- `recall_tokens` in `wisp.json` (default 6000): the ceiling for notes recalled before each reply. `brain_log_markers` (default sessions, daily, digest, session, log): folders and tags whose notes rank lower in brain search, so the topical note beats the session logs about it.
- Codex launches from the app and the Telegram bot now also pass `wisp-brain` as launch overrides, like `wisp-email`, unless the user defined their own `wisp-brain` in the Codex config (`wisp codex check` reports it as `owned`). The Wisp block in the Codex config adds the brain server even when the user owns the email one.
- The brain index survives several processes at once (one writer, waiters re-check what is left), never deletes a busy database, skips binary `.md` files, and recall stays quiet while the index has never been completed. Recall remembers hits and link-only neighbours separately and adds a neighbour only when two hits link to it or it matches the prompt itself.

### Changed

- Recall no longer stops at 3 notes. It hands the agent the strong head of the matches (notes whose title or aliases match the message, up to 8, stopping at a clear score drop) and, within the token budget, notes one wikilink away from them. Small talk injects nothing. The agent is told to call `brain_search`, `brain_read` and `brain_links` freely and to cite the notes it used as `[[wikilinks]]`. The brain-scope guard, once-per-session offering and fail-open behavior are unchanged.

## [0.3.0] - 2026-11-21

- Version 0.3.0 (build 5).

### Added

- Recall: `wisp hook recall` (`UserPromptSubmit`) reads the user's message and, when it matches notes in the brain, hands the agent the notes' paths and snippets before it answers. A note is offered at most once per session.
- Brain learning: `wisp brain colher [--if-due] [--dry-run] [--json]` summarizes Wisp conversations idle for 30 minutes into the brain through the model (uses the user's Claude plan). The app (launch +2 min, then every 10 min) and the Telegram bot (same cadence) call it with `--if-due`; a global lock makes concurrent callers no-ops. The `brain_learn` key in `wisp.json` (default true) turns it off.
- Brain scope guard: `wisp hook guard-brain-scope` runs only in the harvest's model call and refuses any read, write, search or edit outside the brain folder, plus anything under its `.git` or `.obsidian`. Recall is off during the harvest, and recalled notes reach the agent framed as reference data, not instructions.
- Settings > Geral > Brain: shows the brain folder with "Alterar…" (writes the `brain` key of `wisp.json`, keeping every other key and the file mode) and a switch "Aprender com as conversas" bound to `brain_learn`. Changing the folder also moves the profile's memory root, and the tasks file when it pointed at the old `pendencias.md`. When `profile.json` is a link the profile is left alone and the section says it is managed outside Wisp.
- Self-learning: when the user corrects the agent or states a lasting preference ("sempre me responde curto", "nunca apaga sem perguntar"), it is saved as one line in `<brain>/wisp/aprendizados.md` (max 40; the oldest is dropped with a log line) and every new conversation, in the app and on Telegram, starts with those preferences handed to the agent (`wisp hook aprendizados`, `SessionStart`). The agent saves one with `wisp aprender add "<rule>" [--origem ...]`; the brain harvest also adds the ones it finds in an idle conversation. `wisp aprender listar` and `wisp aprender remover <n>` undo.
- Self-learning safety: rules the harvest finds wait in `<brain>/wisp/aprendizados-pendentes.md` until the user confirms them (`wisp aprender pendentes|confirmar <n>|descartar <n>`, or Settings > Brain); the harvest can no longer edit or remove active rules. `ask` permission rules make the engine prompt before `aprender add|confirmar|descartar` (the old auto-allow is revoked on `wisp setup`), and `wisp hook guard-lessons` denies direct writes to the lessons files. A resumed session gets the lessons again when the active set changed, and after a compaction or `/clear` they are always handed again.
- Until the bot answers permission prompts (separate change), `wisp aprender add` from a Telegram session (`-p` without a prompt host) is refused, safely: the `ask` rule is denied instead of prompting.
- Settings > Geral > Brain: "O que o Wisp aprendeu" lists the learned preferences with a remove button on each.
- `wisp arquivos buscar "<texto>" [--tipo pdf|imagem|...] [--desde 7d] [--pasta <dir>] [--json]`: finds the user's files by name and content with Spotlight, newest first, at most 30, never from `~/Library`, hidden folders or the send deny-list; when Spotlight finds nothing (or is unavailable) it searches names in the folder.
- `wisp arquivos organizar <pasta> [--aplicar] [--lixo]` and `wisp arquivos desfazer [<código>]`: sorts the loose files of a folder into Documentos, Imagens, Vídeos, Áudios, Instaladores, Compactados and Outros. It only shows the plan unless `--aplicar`; it never overwrites (suffix " 2") and never deletes; every run is written to an undo journal in `~/.local/state/wisp/arquivos/`. Installers older than 30 days are only suggested for the Trash and go there (recoverable) only with `--aplicar --lixo`.
- `wisp mac abrir | volume | notificar | print [--janela] | bateria | nao-perturbe`: everyday Mac actions for the agent. A missing macOS permission (Automação, Gravação de Tela) comes back as one line in Portuguese, never a traceback.
- The agent instructions (app, Telegram topics and the shipped harness) tell the agent these commands exist, to prefer them, and to show the `organizar` plan and get a yes before `--aplicar`. In the app, `WISP_BIN` is now set on every turn that knows the CLI, not only in shared topics.
- Native agenda: `wisp agenda` reads and manages the Calendar events and Reminders already on the Mac (iCloud, Google, Exchange; no sign-in of Wisp's own), so the agent in the app and in Telegram answers "o que tenho hoje?" from the real calendar instead of guessing. Commands (JSON out, pt-BR errors): `eventos [--de ISO] [--ate ISO] [--hoje] [--semana] [--calendario NOME]`, `criar-evento`, `editar-evento <id>`, `apagar-evento <id> [--confirmo]`, `lembretes [--pendentes] [--lista NOME]`, `criar-lembrete`, `concluir-lembrete <id>`, `calendarios`. It runs through `wisp-agenda`, a helper inside `Wisp.app/Contents/Helpers` that uses the system's full-access Calendar and Reminders permission; the first use asks the user once. Creating, editing and deleting events and reminders always go through the approval card: the `wisp hook guard-agenda` hook (`PreToolUse`, Bash) answers `ask` for every agenda command that is not a plain read (`eventos`, `lembretes`, `calendarios`, `permissao` without `--pedir`), which it auto-allows only when written as `"$WISP_BIN" agenda ...`, `"$WISP_AGENDA_BIN" ...` or the real install path (`~/.local/bin/wisp`, the helper in `Wisp.app`, the running `WISP_BIN`); a look-alike (`./wisp`, `/tmp/wisp-agenda`, `mywisp`) or a command that hides the subcommand (quotes, `$`, globs, braces, `eval`) asks. Explicit `permissions.ask` rules for every mutating subcommand back the hook (they prompt even in bypass mode), so a calendar entry that says "delete everything" cannot get a change through on the agent's word alone. This is best-effort, defense in depth: a copied helper binary, or a script that calls the helper indirectly, is not caught. The agent instructions also say calendar content is untrusted data, never instructions. Editing or deleting an event with guests is also refused unless the command carries `--confirmo`, an extra convention on top of the approval, not the gate. A recurring event is only touched through its per-occurrence id (`<id>@<start>`, shown by `eventos`) or with `--serie` (this occurrence and the next ones, not the whole series). `eventos` is limited to 92 days and 200 items (`"truncado": true`), and `lembretes` lists pending ones plus those completed in the last 30 days. Ajustes > Agenda has "Agenda: permitir acesso", which asks macOS for the access from the app itself and shows its state.
- The instructions of the app, of the Telegram bot and of the harness `CLAUDE.md` block tell the agent to use `wisp agenda` for anything about schedule or reminders, never to guess a time, and to say what it will create, edit or delete before doing it.
- The app's turns now get `WISP_BIN` (not only on a conversation shared in Telegram) and `WISP_AGENDA_BIN` (the helper inside the running Wisp.app, wherever it is installed), and the agenda instruction appears only when the wisp binary is known.
- Meeting capture (step 1 of call transcription, no transcript yet): "Gravar reunião" at the bottom of the panel's sidebar records your microphone (left channel) and the Mac's audio, which is the other end of a call (right channel), into `audio.m4a` (AAC stereo, 48 kHz) under `~/Wisp/reunioes/<YYYY-MM-DD_HH-MM-SS>/` with a `meta.json` (devices, mode, duration, status). It records only after a click. While recording, the notch shows a pulsing red dot and the elapsed time; "Parar gravação" ends it. A recording is refused below 1 GB free and stops by itself under 200 MB. `recordingsPath` in the settings file moves the folder (no screen in Ajustes yet). The call-app bundle-id list (Zoom, Teams, Slack, FaceTime, Discord, WhatsApp, Webex, Skype and the main browsers) is defined for the later "detect and ask" step. The call audio is written to a crash-safe `audio.caf` and encoded to `audio.m4a` at stop; after a crash the next launch recovers it (status `interrompida`). Source stalls, an all-zero Mac channel for 10 s and device changes mid-call (microphone or output switched) are handled and shown as warnings; the two channels are aligned by the audio clocks. Needs macOS 14.2 or newer (the app already requires 15); the app asks for microphone and system-audio permission the first time you record, with pt-BR explanations, and the hardened runtime gets the audio-input entitlement.
- The Wisp folder: the agent now lives in `~/Wisp/` (agente.md, guardrails.toml, modelos.toml, skills/, ferramentas/, conversas/), and its rules and skills are rendered into Claude Code by `wisp harness sync`. Your own text in `~/.claude` is left alone.
- Email tool: Claude can list, read and search your mail and send messages through the Mail app (`wisp mcp email`). Sending always asks you first, in every permission mode: it is a Claude Code permission prompt (the approval card in the app, or Permitir/Negar buttons on Telegram) that the agent cannot answer for you. Your click also gives the email tool a single-use ticket for that exact message, so a copy of the tool started by the agent cannot send anything else; with no Wisp host running (a plain terminal session), sending is refused. Recipients must be single plain addresses.
- Approvals on Telegram: when a tool needs your approval in a Telegram conversation, the bot sends the request with "Permitir" and "Negar" buttons and only you can answer; without an answer in 600 seconds it is denied. A request too long for a Telegram message is denied with "aprove pelo app". The message then says "permitido", "negado", "expirou" or "cancelado".
- Ajustes > Geral shows "Pasta do Wisp" with its current path, "Trocar…" to pick another folder and "Mostrar no Finder". Changing a path moves nothing; it only points the Wisp to the other folder (`wisp config set wisp_dir|brain <path>`).
- A new guard, `wisp hook guard-outbound`, runs with the other engine guards: it blocks, best-effort, Bash commands that send mail around the email tool (osascript or JXA scripts that send through Mail, Python that imports `wisp.email`). Defense in depth, not a guarantee.
- Wisp keeps its own record of every conversation: each message you send and each final reply, from the app and from Telegram, is appended to a file in `conversas/` inside your Wisp folder (the folder you picked in Ajustes), with the engine and model that answered. When Claude's own session is gone (another Mac, a cleaned-up session file), the next message starts a fresh session primed with the recent part of that record, and the conversation carries on with a short note ("↻ a sessão do Claude não estava aqui; retomei pela conversa guardada no Wisp."). Conversations that started before this update keep resuming as before and are recorded from their next message. If the folder cannot be written, the reply still arrives and you get a one-time notice.
- Local models (not connected to conversations yet): Ajustes > Modelo ("Claude" tab renamed) lists the Qwen3 models you can run on this Mac, with size, speed, limits and whether each one fits your memory and disk. "Baixar" installs Ollama if needed and downloads the model with progress and cancel, and refuses when the disk would be left with less than 5 GB. The local engine behind it (`wisp local chat`) has coded guardrails you can edit in `guardrails.toml`: tools allowed per model size, a step limit, loop detection, a confirmation for anything irreversible in every permission mode (sending an email included), asked by the Wisp itself and never by the model (in the terminal `wisp local chat` asks on your keyboard, no answer in 600 seconds denies; a host answers over `--approvals stdio`), and a note in the reply (with a bigger-model suggestion) whenever a task is beyond the model.
- Codex as a second engine: Ajustes > Claude has a "Motor" picker (Claude or Codex) and the choice (`ativo` in `modelos.toml`, set with `wisp config set engine claude|codex`) is followed by the app and by the Telegram bot. Wisp renders your agent into `~/.codex/AGENTS.md` and the email server into `~/.codex/config.toml`, each inside a marked block; everything outside the blocks is untouched. Switching engine in the middle of a conversation starts the new engine from Wisp's saved conversation, with a one-line note. If the chosen engine is Codex and it is not installed or not logged in on this Mac, the reply comes from Claude and says so.
- Under Codex the permission choices become sandboxes, not questions: "Pedir minha aprovação" only reads (Codex cannot ask here), "Automático" and "Sem pedir" are the same: Codex writes only in the working folder, without network and without any way out of its sandbox (Wisp never lets Codex approve its own commands). Codex never runs in your whole home folder. Wisp's guard hooks exist only under Claude; sending an email still asks for your approval in every mode: under Codex the email tool itself asks the app or the Telegram bot (Permitir/Negar, only you can answer) through a private socket before it sends, and sends nothing if there is no answer, a refusal, 10 minutes of silence or no channel to ask on. If the Codex config from an older Wisp lacks that protection, Codex is treated as not ready (the conversation runs on Claude with a note) until you run `wisp harness sync`. Every Codex launch also carries the email server's definition, approval gate included, on its command line, so an old or edited Codex config cannot switch the gate off. Codex is not used in a folder whose `.codex/config.toml` (or a parent's, up to your home folder) defines the `wisp-email` server or cannot be read: the reply comes from Claude with a note naming the file.

### Changed

- Ajustes > Modelo no longer lists static "Claude" and "Codex" rows under the engine switch: the "Motor" card is the only place to pick Claude or Codex, and the model card below it lists only the local models.

### Fixed

- The local engine can send email. After you allow the card in a local conversation, the `wisp-email` tool gets its approval from a single-use ticket the engine mints for that exact email (to, cc, subject, body); before, the tool asked a host that was not there and always refused. A second identical send needs a new allow, and an altered body is refused.
- Codex finds the agenda commands: both the bot and the app set `WISP_BIN` in the Codex process, to the same binary the email server override uses, so `"$WISP_BIN" agenda ...` runs.

## [0.2.2] - 2026-11-19

### Added

- Conversations run side by side: each one keeps its own Claude process, queue and approvals, so switching to another conversation or starting a new one never stops the one that is answering. The sidebar shows a spinner while a conversation answers and a dot for an unseen reply or a pending approval; the 4 most recent idle conversations stay warm, the rest resume on the next message.
- Short conversation names: after the first reply Wisp asks a small model for a 2-4 word title ("Supabase do mycashy"); until then the first message is cut at a whole word. The same name becomes the Telegram topic name when sharing.
- File cards in the app: a file the agent links or sends shows under its reply with icon, name and size (thumbnail for images); click opens documents and media, anything that could run (apps, scripts, installers, unknown types) is only revealed in Finder.
- Sharing to Telegram shows a spinner on the header button and on the conversation row until the topic exists.
- "Continuar no celular" in the app: shares the conversation if needed, posts a hand-off with the last reply, and keeps the agent asking questions as plain text until the user writes from the Mac again.
- Destructive-action guard: `wisp hook guard-destructive` (`PreToolUse`, Bash) blocks, invisibly to the user, commands that would irreversibly destroy their data or Mac (recursive or forced `rm` of `~`, a top-level folder, the brain, `~/Wisp` or a disk root, emptying the Trash, disk erase and format, `git reset --hard` in the brain) and tells the agent to move things to the Trash instead (`trash <path>`). It runs in the app's and the bot's engine guard settings and in `harness/settings.json`; the guard fixture lists the guard hooks (four with `guard-agenda`).
- `wisp topic compartilhar --session <id> --cwd <dir> --nome <title> --json`: opens a topic on an existing session, posts a recap of its last 6 messages and prints `{"thread", "name", "session_id"}`; it refuses a session that is already a topic.
- `wisp topic postar --json` (stdin `{"thread", "user", "reply"}`): posts "💻 <user>" and the reply in the topic, without running Claude; `"arquivos": [<absolute paths>]` also posts the files the user attached in the app (after the "💻" line).
- `wisp topic enviar --thread N [--legenda TEXT] FILE... [--json]`: the agent sends the user files or images in the Telegram topic (photo as photo, the rest as document; at most 10 files of 50 MB, regular files only, never `~/.ssh`, keychains, the Wisp config or the token file). The bot's turns get `WISP_BIN` and `WISP_TOPIC_THREAD` and the instruction to use it, so the agent no longer answers that it cannot send files.
- `/puxar` in any topic: lists the 10 most recent app conversations that are not in Telegram yet as buttons; tapping one opens its topic with the recap. The list is read from the app's `conversations.json` (`telegram.conversations_file` overrides the path).
- Approvals in the chat: when Claude needs permission for a tool in a Wisp conversation, a card under the last message says "O Claude quer <resumo>" (the command for Bash, the path for Edit/Write, the URL for WebFetch), with "detalhes", "Permitir", "Sempre permitir" (only when Claude offers a rule to save) and "Negar". The turn shows "esperando tua aprovação", further requests queue behind the first, and "Negar" tells Claude so it carries on. With the panel closed, the notch shows "O Claude precisa da tua aprovação" (new "Aprovações" switch in Avisos no notch, on by default). Before this, Wisp sessions silently denied anything outside the allow list.
- Ajustes > "Permissões do Claude" and the same choice in the setup's "Teu wisp" step: "Pedir minha aprovação" (default), "Automático" (Claude decides on its own what is safe and may run destructive actions without asking) and "Sem pedir (perigoso)", which asks for a confirm. It is saved as `agent.permissionMode` in the profile and applies to new and resumed sessions; an idle session restarts at once, a busy one after its turn, and the chat says "o novo modo de permissão vale depois desta resposta" so a stricter mode chosen mid-reply is not mistaken for already active. A `permissions.defaultMode` in `~/.claude/settings.json` shows as "Definido no Claude" and is never rewritten. A profile that is a symlink is not written through: the choice stays in Wisp's settings, which the bot on the same Mac reads too.
- Telegram bot: honours `agent.permissionMode` from the profile (or Wisp's own setting when the profile is a symlink) and logs the mode of each turn. Without it the bot keeps running without asking; "Pedir minha aprovação" runs as Automático there, since Telegram cannot show the card yet. If the account refuses Automático, the turn runs once more in `acceptEdits` (edits allowed, other commands refused), never without asking.
- The approval card always shows the whole command or input in a scrollable block. When the one-line summary is cut, or a command spans several lines or chains commands (`;`, `&&`, `|`, `$(`...), the card says "comando longo — veja inteiro" and Permitir / Sempre permitir stay off until the full text was opened. The same lock holds for any tool whose input carries something the summary leaves out: the new content of a Write, Edit, MultiEdit or NotebookEdit, and the other arguments of an MCP or unknown tool ("veja o conteúdo inteiro"); reads and searches (Read, Glob, Grep, WebFetch, WebSearch) never lock. If the answer cannot reach Claude, the card stays and the chat says so.

### Changed

- The Telegram bot and the Mac app are two surfaces of one conversation. The conversation is the Claude session: sharing it to Telegram opens a topic on the same session and the same folder (nothing is copied), and each surface runs its own turns. A per-session lock (`~/.local/state/wisp/locks/<session_id>.lock`) keeps the two from running a turn at once; when the bot has to wait for the app, the topic says "respondendo no app, esta vem logo depois".
- Mac only: the app no longer routes a turn through the bot, and the "who is reading" claim (`wisp topic assumir`), `wisp topic falar` and the CLI `wisp topic puxar` (pulling a session between machines) are removed, along with the bot's `falar`, `adotar` and `trazer` requests. The new Telegram `/puxar` command is unrelated to the old CLI one: it lists app conversations to share into Telegram (below). `wisp topic status --json` always reports this Mac as reader and claim.

- The files the agent may send to Telegram are screened by a wider deny-list, kept identical in the bot and in the app: any `.env`/`.env.*`, `.netrc`, `.git-credentials`, `.pgpass`, `.npmrc`, `.pypirc`, `id_rsa*`/`id_ed25519*`/`id_ecdsa*`, `*.pem`, `*.p12`, `*.pfx`, `*.keychain`, `*.keychain-db` (any folder, any case, also through a symlink), and the folders `~/.kube`, `~/.docker`, `~/.config/gcloud`, `~/.azure`, `~/.config/gh` and `~/.password-store` on top of the ones already blocked. Both sides keep the same list in code; the contract fixture `cli/tests/fixtures/contract/send-denylist.json` is a drift test that fails if they differ. `.key` files are no longer refused by name, so Keynote decks (zip files) can be sent; instead any file whose first 4096 bytes contain `PRIVATE KEY-----` is refused (a failed read is refused too), which still blocks PEM/OpenSSH private keys under any name.
- File-open policy: `.mobileconfig`, `.jnlp`, `.ics`, `.webarchive`, `.html`/`.htm`/`.xhtml` and `.svg` files a link points at are now revealed in Finder instead of opened.
- Ajustes is split into tabs at the top (Aparência, Claude, Avisos, Integrações, Geral, Sobre) instead of one long scroll of cards; only the selected tab's content scrolls. Each card is a header over aligned rows (label left, control right), and a switch row flips from anywhere on the row. The last tab opened is kept in `settings.json` (`settingsSection`) and reopens next time; "Abrir Ajustes" from the Spotify steps in Música lands on Integrações. Sobre is new: version, GitHub link, license (GPL-3.0) and Avisos de terceiros, which moved there from the Setup card.
- Version 0.2.2 (build 4).

### Removed

- The bot's old terminal "vigia"/modo celular code (`vigia.py`, `_adotar_celular` and friends): nothing reached it any more.

### Fixed

- Closing a topic asks "Encerrar «nome»?" on two lines with Encerrar / Cancelar instead of a truncated one-line "Encerr… Sim Não".
- "Manda aqui o arquivo" typed in the app now delivers the file in the app. The instruction used to depend on the conversation being in Telegram, so an app turn on a shared conversation sent the file to the phone (the agent even wrote its own Telegram call with the bot token) and nothing showed up where the user was reading. Now an app turn always hands files over as a `file://` link; the shared-topic note says links are mirrored to the topic automatically and `wisp topic enviar` is only for an explicit request. Both the app's and the bot's instruction forbid calling the Telegram API directly or reading the bot token. After an app turn on a shared conversation, the `file://` links in the reply (existing regular files, up to 10) go to the topic as attachments of the mirrored post.
- One conversation, one format and one set of abilities on both surfaces. The shared session now speaks Markdown: the bot used to ask Claude for Telegram HTML, which the app showed raw (`<b>Slack:</b>`, `<a href=...>`). The bot converts Markdown to Telegram HTML on every send path (replies, the share recap, the app's mirrored turns, file captions); the app turns the HTML already in old history (`b strong i em code pre a u s br blockquote` and `&lt; &gt; &amp; &quot;`) into Markdown, live replies included.
- A turn run by the app now gets what the bot's gets: on a conversation in Telegram, `WISP_BIN`, `WISP_TOPIC_THREAD` and the same instruction to send files with `wisp topic enviar` (so "me manda o arquivo aqui" sends it to the topic instead of "I cannot"); on any other conversation "here" means the app, and Claude hands a file over as a `[name](file:///abs/path)` link that opens on click (a program is only shown in Finder, never run). The `claude` process restarts when the conversation moves to another topic or out of Telegram, since env and prompt are fixed at start.
- Files reach the user only through Wisp, and Wisp now enforces it itself. The agent copied an earlier turn and posted a file straight to `api.telegram.org` with the bot token. A new `wisp hook guard-telegram` blocks Bash and file-tool calls that use the Telegram API, read the bot token file or read the token through the bot's config, and says the right way (a `file://` link in the app, `wisp topic enviar` in Telegram). The app and the bot start every `claude` with `--settings` pointing at a Wisp-owned file holding the secrets and Telegram guards, so they hold even when the user never ran `wisp setup harness`; users of the harness get the same hook plus a rule in the `CLAUDE.md` block. The file instructions now say a guard blocks direct API use.

## [0.2.1] - 2026-11-18

### Changed

- Release and the maintainer's local builds are signed with a stable self-signed identity, "Wisp Self-Signed", instead of ad-hoc. The designated requirement is now the certificate, not the build's hash, so Keychain "Always Allow" (the Spotify login) and macOS permission grants survive rebuilds and updates; after updating from 0.2.0 they are asked one last time. `scripts/build-release.sh` uses `WISP_SIGN_ID` if set, else this identity when it is in the keychain, else ad-hoc. Contributors without it still build ad-hoc; `app/Local.xcconfig.example` shows the optional local override. Version 0.2.1 (build 3).

### Fixed

- CPU with the notch visible: the Wisp avatar now animates in Core Animation instead of a 30 fps SwiftUI timeline that re-laid out the whole pill or panel every frame (Release, idle: pill 2.5% -> 0.1%, panel 5.6-10.4% -> 0-1.1% depending on the tab). Opening Início no longer re-reads a week of Claude transcripts each time: the usage tile keeps what it read and reads only appended bytes (a repeat refresh went from 1.8 to 0.05 CPU-seconds on 370 MB of transcripts). Debug and `WISP_PERF` builds take `-WispOpenPanel <tab>` to open the panel on a tab and keep it open, and `-WispNoKeychain` to skip every keychain read and write (Spotify shows as not connected), for measuring without the keychain prompt.

## [0.2.0] - 2026-11-18

### Added

- Automatic updates with Sparkle 2.10.1: a daily check of the GitHub release feed; a new version shows the notch notice "Versão nova do Wisp — x.y.z" (new kind with its own switch in Ajustes > Avisos no notch, on by default), and a click opens Sparkle's window with release notes and "Install and Relaunch". Nothing installs without the user. Ajustes > Atualizações shows the version, "Verificar agora" and "Verificar automaticamente". Version 0.2.0 (build 2).
- Release: `scripts/build-release.sh` also writes `dist/appcast.xml`, EdDSA-signed with the maintainer's Keychain key, pointing at `releases/download/v<version>/Wisp.dmg`; `scripts/publish-release.sh <version>` checks the tree is clean and pushed, tags and creates the GitHub release with the DMG and the appcast.

## [Unreleased] - 2026-11-17

### Added

- App icon and a styled disk image: the Wisp mascot on a dark macOS tile (`AppIcon` asset catalog, 16 to 1024 px) shows in Finder, the Dock and Login Items, and `dist/Wisp.dmg` opens a 640x400 window with the title, the app on the left, an arrow to Aplicativos on the right and the icon as the volume icon (built with `dmgbuild` 2.0.0 via `uvx`). `scripts/render-art.sh` regenerates the icon set and the DMG background from the real avatar.
- Release build: `scripts/build-release.sh` builds the Release app and packs `dist/Wisp.dmg` (drag to Applications) and `dist/Wisp.zip`. The default signature is ad-hoc with no notarization; `WISP_SIGN_ID` (Developer ID, hardened runtime) and `WISP_NOTARY_PROFILE` (notarization) are optional. pt-BR install guide in `docs/instalar.md`.
- First-launch setup wizard in its own window: it waits for the runtime install ("Preparando o Wisp", with "tentar de novo" on failure), then walks system (optional Homebrew), login, brain, harness, Telegram (optional), Spotify (optional) and the profile, showing each step's real command under "detalhes". It can be run again from Ajustes > "Rodar o setup de novo"; existing installs are not sent through it.
- The wizard's login step is a real terminal (SwiftTerm): the user runs their own `claude` and types `/login`; the step turns done once the login is detected, and "Pular por enquanto" skips it.
- Bundled runtime: the app ships `uv` 0.13.5 (universal, pinned sha256, `scripts/fetch-uv.sh`) and the Python sources. On first launch they are copied to `~/.local/share/wisp/runtime`, uv runs from a copy without the quarantine flag (the bundled one blocks on Gatekeeper after a download), `uv sync` and `wisp setup shim` run, and an unchanged runtime is not reinstalled.
- Ajustes > "Abrir ao ligar o Mac" (default on): Wisp registers as a login item once, only when it runs from /Applications or ~/Applications. A removal in System Settings is respected, and the switch shows the real macOS status.
- Notch notices: a reply in a conversation not on screen, a new Telegram topic message, a new alert or reminder, and an outbox message sent or marked "não enviada" grow the pill into a card under the notch; it folds after 6 s, pauses on hover, and a click opens the matching tab. Ajustes > "Avisos no notch" has one switch per kind and "Não perturbe". Wisp never uses macOS notifications.
- Telegram delivery (D15): with Telegram configured a conversation never runs locally. Every message goes into a persisted outbox first, waits "na fila" while the bot is down, survives a quit, retries after 10, 30 and 60 s, then shows "não enviada · tentar de novo · descartar".
- `wisp` CLI (Python, uv workspace `cli/` + `bot/`): `wisp doctor --json`, `wisp setup system|brain|harness|telegram|profile|shim`, each with `--json` and most with `--dry-run`.
  - `setup system [--with-homebrew]`: checks the Command Line Tools, installs Claude Code with its official installer, and optionally installs Homebrew from its signed `.pkg`.
  - `setup brain`: creates a local git brain from `vault-template/` (default `~/Wisp/brain`), keeping existing files.
  - `setup harness`: installs the generic harness into `~/.claude` with a backup first, merges `CLAUDE.md` and `settings.json`, keeps any file the user edited, and is idempotent.
  - `setup telegram --token-stdin | --discover | --skip`: validates the bot token (read from stdin, stored 0600), finds the forum group and the user, and installs the `ai.wisp.bot` launchd job.
  - `setup profile`: writes `~/.config/wisp/profile.json` (persona, user name, language, avatar).
- Generic `harness/`: a `CLAUDE.md` block, reader/operator/reviewer roles, `brain-boot` and `save-to-brain` skills, `/diagnose`, and hooks: `wisp hook boot` (date and pending items), `wisp hook brain-commit` (commits brain changes locally, holds back files that look like secrets, never pushes) and `wisp hook guard-secrets`.
- Secrets guard: `wisp hook guard-secrets` (`PreToolUse`) blocks Bash and file-tool calls that point into the Wisp secrets folder, after normalising `~`, `$HOME`, `..` and symlinks; the `permissions.deny` rules stay as a second layer.
- `wisp-bot`: the Telegram bot as its own package, configured from `wisp.json`. `solo` hosting reads Telegram on one machine; `pair` hands a conversation off between two machines over ssh. Brain sync and alerts run only when their command is configured.
- `wisp topic status|listar|novo|falar|encerrar|assumir|puxar`: the topic CLI; `falar --anexo <file>` (repeatable) sends files as photos or documents.
- Background jobs interface with a launchd implementation; Linux and Windows report "not supported yet".
- `scripts/leak-check.sh`: gitleaks, the shared secret patterns and a generic identifier list over `app`, `core`, `cli`, `bot`, `harness`, `vault-template`, `docs` and `scripts`; an optional git-ignored local list adds personal patterns.

### Changed

- The app's bundle id is `ai.wisp.app`; settings and the Spotify login from the previous id are copied over once. The bot's launchd label is `ai.wisp.bot`.
- Conversation rows show a one-line preview of the last message under the date ("Você: …", attachments as "📎 foto"/"📎 arquivo").
- Início: the "Última conversa" tile is now "Conversas": the most recent Wisp and Telegram conversations, as many as fit.
- Pill avatar takes its gradient from the theme accent, breathes, blinks and glows while the agent works; "Reduzir movimento" freezes it. The pill dot shows only for an unread notice or a conversation in error.
- Telegram with two machines: sending from Wisp while the other machine reads the bot first brings the conversation over, then sends; if that fails, one sentence explains it and nothing is sent.
- `wisp doctor --json` reports a warning and default settings when `wisp.json` is unreadable.

### Fixed

- The Claude Code installer is downloaded over HTTPS to a file and run from it instead of `curl | bash`.
- The bot's ssh helper kills its whole process group on timeout.
- Closing the conversation list slides it out as the exact reverse of opening it.
- The command runner no longer crashes when a timed-out child has already exited.
- Invalid graph settings fall back to the defaults and say so instead of resetting silently.

## [Unreleased] - 2026-11-16

### Added

- Memória graph view: Obsidian-style link graph of the vault (wiki links, embeds, aliases), hover highlights neighbours, click opens the note, local graph, folder colours.
- Música with the Spotify Web API: login with PKCE (tokens in the Keychain), playlists, search, play and add to queue, using the user's own Spotify app.
- Initial app: `core/` (WispCore, SwiftPM) and `app/` (Wisp.app, xcodegen, menu-bar agent for macOS 15+, Swift 6).
- Profile loaded from `~/.config/wisp/profile.json` (persona, agent cwd and model, block commands).
- Agent engine driving the user's installed Claude Code (`claude -p` stream-json), one long-lived session per conversation; past transcripts read from `~/.claude/projects`.
- Notch shell: a pill hugging the camera notch; the panel opens on hover, click or ⌥Space and closes with Esc or an outside click.
- Panel tabs: Início (draggable tiles), Conversa (Wisp and Telegram), Memória (vault search, recent notes), Tarefas, Lembretes, Agenda, Rotinas (launchd jobs), Música, Copiados (clipboard history that skips password managers), My Mac (system, CPU, memory, disk, temperature, battery, network, top processes) and Ajustes (themes, custom colours with a contrast guard).
- Now Playing for Spotify and Music via AppleScript; never launches a player.
- Claude plan usage: session and weekly limits from the status line, plus token totals from transcripts.
- Telegram: with the bot configured, a Wisp conversation is a Telegram topic; replies are read live from the session transcript.

### Changed

- Memória graph is a live force simulation: drag a note and its neighbours follow, pan with momentum, zoom at the cursor, labels fade in with zoom, and a Forces panel saved in settings. It draws only while something moves.
- Conversa: the conversation list slides over the sidebar; a button or ⌘N toggles between the list and the menu.
- Telegram section hides topics whose note is closed.
- My Mac scrolls inside the tab, shows real free space for network volumes, and sparklines span the tile width.
- Scroll bars are hidden in every pane.

### Removed

- Timers tab and the timer ring in the pill.
