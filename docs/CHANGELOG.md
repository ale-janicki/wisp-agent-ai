# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Entries are in descending chronological order (newest first).

## [Unreleased]

### Fixed

- Ajustes > Modelo: choosing Claude or Codex when the harness is managed outside the Wisp (your own `~/.claude`) no longer shows a red "harness não sincronizou" line. The engine is saved and the note "o harness é gerenciado fora do Wisp, então ele não foi alterado" appears as secondary text (`wisp config set engine|wisp_dir|brain` report `done` with `data.harness = "managed_elsewhere"`); real harness failures stay red.
- Ajustes > Modelo (and the Conversa tab settings): with Claude or Codex as the engine the local-model recommendation, "Pensar antes de responder" and the "Neste Mac" list are collapsed behind one "IA local neste Mac" row ("Ver modelos locais", closed by default); with IA local everything shows as before.

### Added

- Ajustes > Modelo (and the Conversa tab settings): "Conectar Claude" and "Conectar Codex" open Terminal with the login already typed and run (`claude`, then type /login; `codex login`) and wait for it ("Esperando o login no Terminal…", then "Conectado"); with the CLI missing nothing opens and the card shows how to install it. In setup, an engine that is not connected says "Conecte em Ajustes > Modelo".
- Meetings: the live recording screen keeps the transcript at a readable width (side panel sits below it when the tab is narrow), recorder controls sit in one row, the copilot and conversation cards are compact ("Ainda sem fala" instead of rows of zeros), and a finished meeting's note renders as Markdown (headings, lists, bold, links, wikilinks) like the Brain reader; "Copiar" still copies the raw Markdown.
- Setup is one screen: a "Preparando o Wisp…" line while the runtime installs (with "Tentar de novo" on failure), "Este Mac" (chip, memory, free disk) and three engine cards side by side. IA local is selected by default with the model recommended for the Mac already picked in a dropdown (every catalog model with size and speed, "Recomendado", "Já baixado", "Apertado", and "não cabe" disabled); Claude and Codex are choices that show "Conectado" only when the CLI is already logged in, otherwise "Conecte em Ajustes > Modelo". "Começar" creates the brain (or keeps the configured one), installs the harness, selects the engine, saves the profile with defaults and starts the model download in the background, with errors inline and "Tentar de novo".
- Ajustes > Modelo and the Conversa tab settings have a "Telegram" card ("Conectar Telegram": token, group search, disconnect); Ajustes > Geral has a "Perfil" card (Wisp name, your name, image).
- Meetings: opening a meeting now covers the sidebar like the Conversa tab (back arrow and a hide/show menu button), the recorder is a compact bar at the top of the list (one "Gravar" button, timer and one level meter only while recording; the auto-summary option stays in the tab settings), and the detail is cleaner: title, one status line, one primary action plus a "…" menu, a single inline error line with "Tentar de novo" ("A nota não foi gerada. Tente de novo." for a failed note command), and the note in a centered readable column. With nothing selected the tab shows a centered message with the record button.
- IA local: the agent's rules (`agente.md`) are now filled in with the persona, user, language and brain folder before the model reads them, so it no longer answers with `{{USER_NAME}}` or `{{BRAIN_DIR}}`; the file on disk is not changed.
- IA local: the model now knows its own name ("Qwen3 8B" instead of the size tier), whether it has web tools, and a short list of what the enabled tools let it do, so it stops saying it cannot reach the internet when it can.
- IA local: the prompt prefix (rules, tools) is the same on every turn and today's date moved to the end of each message, so mlx-lm's prompt cache is reused and replies after the first one start faster.
- Ajustes > Modelo: when the Mac has little free memory right now, the recommendation is one model lighter and says "o Mac está com pouca memória livre agora" (also in `wisp local recomendar`, new `--available-bytes`).
- The "pensando…" row in the conversation shows the elapsed seconds after 5 s.

### Changed

- Setup no longer has a step sidebar, a system-tools step, a Claude login, Telegram, Spotify or profile editing: Telegram and the profile moved to Ajustes, Spotify stays in the Música tab settings, and setup never downloads or installs the Claude CLI, Obsidian, the Command Line Tools or Homebrew.

## [0.4.2] - 2026-11-22

- Version 0.4.2 (build 9).

### Added

- Each tab with settings (Conversa, Brain, Agenda, Reuniões, Música, My Mac) has a gear in its header that opens that tab's settings inside the tab, with "Voltar" and "Todos os ajustes"; Ajustes keeps everything.
- Meetings: the meeting note now goes into the brain by itself. When a recording starts and no event was picked, the Agenda is asked (only if Calendar access was already granted) for the event that overlaps the start, and its title, attendees, organizer, calendar, notes and call link are saved with the recording. When the meeting is processed, `wisp reuniao brain` writes `meetings/YYYY-MM-DD-HHhMMm-slug.md` (plus a line in `meetings/meetings-index.md` when that index exists) in the brain with the date, duration, attendees, calendar and recording path in the frontmatter, a "Participantes" line, the summary sections when they exist and a link to the transcript.
- Meetings: attendees and the people, projects and clients named in the summary become `[[wikilinks]]` only when the brain index finds exactly one existing note by title, alias or file name; no match or more than one match stays plain text, and no note is ever created for a link.
- Meetings: the "Salvar no brain" button now runs the same sync instead of copying the note, and reads "Abrir no brain" once the synced note exists.
- Meetings: new setting "Gerar resumo logo após a chamada" in Ajustes > Geral > Reuniões and on the Reuniões tab (on by default). Off writes the brain note with participants and the transcript link right away and the finished meeting shows "Gerar resumo", which fills the same brain note.
- Ajustes > Geral > "Pasta do Wisp" is one compact row: the "Trocar o caminho não move nada" note moved into the "Trocar…" tooltip and the list of what is inside the folder sits behind a closed "O que tem dentro" disclosure.
- `wisp local delete TAG` removes a downloaded model (and its partial download); `wisp local catalog` now also reports `downloading` and `resumable` tags.

### Changed

- The "Memória" and "Brain" sidebar tabs are now one "Brain" tab: the recent notes list, the command search and the graph search moved into it (home view when no note is open, "Visão geral" button).
- Ajustes > Modelo list redesigned: one grouped card, one row per model (name, size, memory and speed on one line, at most two tags, one trailing button) and the long description behind "Detalhes". The recommendation card says "Usar Qwen3 8B (já baixado)" when the model is on disk.
- Ajustes > Sobre now holds Atualizações (version, Verificar agora, automatic checks) at the top, instead of the end of Geral; the duplicate version row in Sobre is gone.

### Fixed

- Meetings: a brain note that was renamed or moved is found again (by its `gravacao` and marker) and updated in place instead of duplicated; if it was deleted, the sync says so and only recreates it on an explicit "Salvar no brain". Event text can no longer inject lines into the note, concurrent writes to the meetings index and summary are serialized and re-checked, and the note stores `~`-relative paths instead of absolute ones.
- Local models: two downloads of one model can no longer both run after a status poll removes a stale lock at the wrong moment (the lock is re-checked after it is taken); deleting a model stops its server first; deleting a model whose folder is a symlink removes the link without following it, and a delete that fails is reported instead of "done".
- Ajustes > Modelo: a model whose download finished is shown as downloaded ("Usar" / "Em uso" and "Apagar") even when an interrupted download left a stale `.baixando-<model>.lock` or `modelos.toml` never recorded it. The list reads the folder (config.json plus every shard of `model.safetensors.index.json`, or `model.safetensors`, all non-empty); a lock nobody holds is removed; an incomplete folder offers "Retomar download".
- The "mlx-lm missing" message no longer tells the user to update the Wisp. It says the local AI component is still being installed (the install was interrupted), that it finishes by itself, and offers "Tentar de novo".
- The runtime install no longer breaks when the bot is writing into the installed sources: the new `src` is copied beside the old one and swapped in by rename, the old folder is removed best-effort (leftovers are swept at launch), and runtime Python no longer writes `.pyc` files. Before, a half-deleted `src` made every launch fail with "Não consegui copiar os arquivos do Wisp".

## [0.4.1] - 2026-11-22

- Version 0.4.1 (build 8).

### Fixed

- The app no longer quits by itself while the Brain tab is open. The Brain's file watcher read the changed paths as objects while macOS sent them as C strings, so the first change in the brain folder crashed the app. The stream now asks for CF types, and the watcher's handler stays alive until the stream is invalidated. A crash in the middle of the first runtime install also left `mlx-lm` missing; the install resumes on the next launch.
- A brain folder saved as `~/…` counts as existing: the harness step no longer fails with "falta criar o cérebro antes", `BRAIN_DIR` is passed expanded, and the doctor's brain check expands it too.

## [0.4.0] - 2026-11-22

- Version 0.4.0 (build 7).

### Added

- Brain: "Novo desenho" and "Novo canvas" create an empty Excalidraw drawing (`Desenho yyyy-MM-dd HH.mm.excalidraw.md`) or JSON Canvas (`Canvas yyyy-MM-dd HH.mm.canvas`) in the folder of the open note (toolbar button, the ... menu) or in the folder you right-click in the tree. A taken name gets " 2", " 3"; an existing file is never overwritten. The new file opens in a new tab and shows in the tree and search like any other drawing.
- Local AI works in the app and on Telegram. Choose "IA local" as the engine (Ajustes > Motor, `wisp config set engine local` or `/modelo local` in Telegram) and the conversation runs on a Qwen model on this Mac through MLX (`mlx-lm`, pinned, no separate app), with the same approval cards as Claude: a tool that writes, runs a command or sends an email waits for your Permitir/Negar in the app or in Telegram, and an email still needs the single-use ticket. If the runtime, the server or the chosen model is not ready, that turn runs on Claude with one line saying what is missing and that Ajustes > Modelo fixes it. Switching to and from the local engine keeps the conversation (it is rebuilt from the Wisp transcript, recorded with engine `local` and the model).
- Any OpenAI-compatible server can be the model backend instead of MLX: `wisp local backend openai --url http://127.0.0.1:1234 --model NAME` (LM Studio, llama.cpp server, vLLM; the server must support tool calling), `wisp local backend mlx` goes back. An API key, when the server wants one, comes from `WISP_LLM_API_KEY`.
- The local engine can search and read the web: `web_search` (DuckDuckGo's HTML page, no key) and `web_fetch` (http/https text pages only, never the local network, connecting to the address it checked). A search is free until the conversation has run any other tool (a file, a note, an email, a page, a command, a tool from `ferramentas/`), or when the query is long (over 120 characters); then it asks for your approval and shows the whole query, even in later turns of the same conversation. A fetch is free only for an address from that turn's search or one you typed, and anything else asks in every mode. What comes back is shown to the model as data to read, never as instructions.
- The MLX server is never reachable from the network or by another process through a port: it sits behind a small local proxy with a random key per start and listens on a private Unix socket, not on any port, serves only the active model, cannot download anything, stops after 15 idle minutes (`idle_minutes` in `modelos.toml`) and when you switch the engine away from local. Macs without Apple silicon are told plainly and offered the OpenAI-compatible URL backend; model downloads take a per-model lock and swap in atomically.
- "Melhor para este Mac" and "Mais rápido": Ajustes > Modelo reads your chip, memory and free disk and recommends the most capable model that fits with room to spare and the smallest one that still uses tools reliably, each with "~N palavras/s (estimativa)" computed from Apple's published memory bandwidth ("sem estimativa" for a chip Wisp has no figure for), and nothing local fits it says so and points to Claude or Codex. One button, "Usar IA local", downloads the recommended model (with progress and cancel), activates it and switches the engine; if anything fails the engine stays as it was. The same offer shows in the setup step "Teu wisp". `wisp local recomendar --json` prints the same recommendation.
- "Pensar antes de responder" (Ajustes > Modelo, `[local] pensar` in `modelos.toml`, `wisp local pensar on|off`): off by default, so the local Qwen answers right away (a short answer starts in about 0.3 s instead of about 16 s); on, it reasons first. `/modelo` on Telegram shows the setting.
- Telegram `/modelo` shows the active engine, the local model and the recommendation, and `/modelo claude|codex|local` switches the engine for the app and the bot.
- Brain search for every engine: `wisp mcp brain` is an MCP server (`wisp-brain`) with three read-only tools. `brain_search(query, limit)` ranks notes by title, aliases, headings and text (BM25) with a boost from the wikilink graph; `brain_read(path_or_title)` opens a note by name, alias, path or `[[wikilink]]` (`#heading` and `|text` work) and returns it with its outgoing links and backlinks; `brain_links(note, depth)` walks the link graph. The index is a local SQLite file in the Wisp state folder that updates itself when files change; nothing leaves the Mac. `wisp setup harness` registers it in Claude and in the Codex config; the local engine has it built in.
- `recall_tokens` in `wisp.json` (default 6000): the ceiling for notes recalled before each reply. `brain_log_markers` (default sessions, daily, digest, session, log): folders and tags whose notes rank lower in brain search, so the topical note beats the session logs about it.
- Codex launches from the app and the Telegram bot now also pass `wisp-brain` as launch overrides, like `wisp-email`, unless the user defined their own `wisp-brain` in the Codex config (`wisp codex check` reports it as `owned`). The Wisp block in the Codex config adds the brain server even when the user owns the email one.
- The brain index survives several processes at once (one writer, waiters re-check what is left), never deletes a busy database, skips binary `.md` files, and recall stays quiet while the index has never been completed. Recall remembers hits and link-only neighbours separately and adds a neighbour only when two hits link to it or it matches the prompt itself.
- Meetings tab: "Reuniões" in the sidebar opens a screen with the list of your meetings (date, duration, title, status: gravando, transcrevendo, gerando nota, pronto), a big Gravar/Parar button with the timer, live input levels for the microphone and the Mac's audio, and a source picker (microphone, Mac audio, or both). A missing microphone or audio permission shows a card with a button to the right System Settings pane instead of a line of small text. The sidebar's old "Gravar reunião" row is replaced by the tab (its row shows the red dot and timer while recording).
- Live transcript: while you record, what is said appears as lines with the time and "Você" (microphone) or "Outros" (Mac audio); it follows the end and you can scroll back ("Ir para o fim"). It runs fully on the Mac with Parakeet TDT 0.6b v3 (FluidAudio, Neural Engine) in 5 s windows with 1 s overlap, with partial lines that become final.
- Speech model download: the tab offers the model (0.6 GB, 20 files from `FluidInference/parakeet-tdt-0.6b-v3-coreml`, CC-BY-4.0) once, into `modelos/` in the Wisp folder, with progress and cancel, a free-disk check and a SHA-256 (or git SHA-1) check of every file; without it the recording still works and is transcribed after the download.
- After you stop: a clean transcript pass over the whole audio (`transcript.json`), then a meeting note written with no tools by Claude (never by Codex, whose shell can read any file on the Mac: with Codex active the note is written by Claude, else by the ready local model, else skipped with "Nota não gerada: …"): summary, decisions, action items with owner. The note is `nota.md` in the meeting folder (new `wisp reuniao nota <folder>`); if the engine fails you get a note with the transcript and the reason, never nothing. The meeting has Abrir nota, Copiar, Salvar no brain (`<brain>/meetings/`), Gerar nota de novo and Mostrar no Finder.
- A recording recovered after a crash is transcribed and gets its note like any other.
- Hardening: the note engine runs with no tools, no MCP servers and no hooks in a temp folder; the transcript is fenced as data; a long transcript keeps its start and end and says the middle was omitted; one note per meeting at a time (lock file), and quitting or cancelling stops the note process. Silence on the Mac channel only shows a hint during that recording and is never remembered as a denied permission. The model is re-checked by SHA-256 on load, swapped in atomically, and its manifest paths are validated. The FluidAudio license ships with the app (Ajustes > Sobre > Avisos de terceiros) and the package is pinned by commit. Only one speech model is resident in memory at a time. A heavy live recording shows "Transcrição atrasada" instead of dropping text, the final pass waits while you record, and live times share one clock. The brain index line is sanitized and a symlinked `meetings` folder outside the brain is refused. The model's CC-BY-4.0 attribution is on the download card and in Ajustes > Sobre.
- `meta.json` now records `sources`, `title`, `note_file`, `note_state` and `brain_note`.
- Wisp folder for the whole product: `conversas/`, `reunioes/`, `brain/`, `modelos/` (local models), `anexos/`, `skills/`, `ferramentas/`, `logs/`, `agente.md`, `guardrails.toml` and `modelos.toml` under one folder, resolved the same way by the app, the CLI and the Telegram bot (shared contract fixture). Secrets, the runtime and app state stay outside it.
- `wisp folder migrate`: on the first launch after the update, small attachments from the app and from Telegram move into `anexos/` (large ones stay and are reported). Each item moves with an atomic no-overwrite rename, a second run finishes what a first left, if the destination exists both stay and it is reported, a `MOVIDO.txt` stays at the old place and `logs/migracao.log` is written as each item moves.
- Ajustes > Geral offers "Mover reuniões" after the Wisp folder changes: recordings never move on their own, and the move shows progress, has no timeout and can be run again.
- A Wisp folder upgrade keeps a non-empty `~/Wisp/brain` as the brain instead of switching to an empty one.
- Ajustes > Geral lists the subfolders of the Wisp folder and what each holds, next to "Mostrar no Finder".
- `wisp topic unir [--aplicar] [--forcar]`: rejoins conversations split by a session id change (records sharing a transcript by session links, records of a topic's session, and every record titled like the Geral) into one. Without `--aplicar` it only prints the plan. With it, it refuses while the app is open or the bot is reading (unless `--forcar`), copies `conversations.json`, `topics.json` and the transcripts it touches to `<wisp_dir>/backup-conversas/<time>/`, merges the transcripts in time order, imports the text of sessions that had no transcript from the Claude session files, writes `unir.log` there and sets the topic's `conversation`.
- Mac control: the agent can now act on the Mac instead of describing how: open an app, a file in a chosen app or a site in a chosen or the default browser ("abre o YouTube", "toca lo-fi no YouTube", "pesquisa X no Google"), focus, hide or quit an app, list apps and windows, volume and mute, play/pause/next on Music and Spotify, brightness, dark mode, Wi-Fi state, battery, a Settings pane, a screenshot of the screen or of one app's window, a Shortcut by name, and AppleScript or JXA. The same tools exist in every engine: `wisp mac <command>` (new: `abrir-url`, `app`, `apps`, `janelas`, `midia`, `brilho`, `modo-escuro`, `wifi`, `ajustes`, `atalhos`, `atalho`, `script`, `arvore`, `clicar`, `digitar`, `tecla`, `rolar`, `menu`; `abrir --com <app>` and `print --app <app>`), the `wisp-mac` MCP server (`wisp mcp mac`, registered for Claude Code by `wisp setup harness` and for Codex in the managed `config.toml` block and the app/bot overrides) and built-ins of the local engine.
- Screen interaction through the Accessibility API: `wisp-mac`, a helper in `Wisp.app/Contents/Helpers` (AX tree, press, menus; CGEvent typing, keys, point clicks and scroll). It reads the front window as numbered elements (role, title, value, position), clicks by title or role or at a point, types, presses keys and shortcuts, scrolls and picks a menu item by path. Without the permission it fails at once with a message that points to Ajustes > Controle do Mac, and it never hangs (25 s watchdog, 2 s per AX call). `wisp-mac selftest` checks its parsers without touching the UI.
- Ajustes > Geral > Controle do Mac: shows the Accessibility and Automation state and has one button that asks and opens the right System Settings pane, with a sentence on why each one is needed.
- Safety: reading tools run without a card; tools that change things follow the permission mode. Clicking, typing Return or using the Send menu in Mail, Messages, WhatsApp, Slack, Telegram, Signal, Discord, Outlook or Teams is refused; sending goes through the new `mac_send` tool, which checks that the text and recipient are what is on screen and asks for approval like `email_send` (card in the app, Telegram card, local-engine card). Typing into a password field is refused and its value is never read. Scripts are checked against the destructive and outbound guards before they run, and `wisp hook guard-outbound` blocks driving the helper directly from a shell. Every call is logged to `~/.local/state/wisp/mac-acoes.jsonl` (typed text only as its length).
- The agent instructions (app, Telegram, Codex and the harness `CLAUDE.md` block) now say the agent controls the Mac and must act, with examples (YouTube, Google, a file in Preview).

- Agenda tab: a full calendar for the Calendar accounts already on the Mac (iCloud, Google, Exchange). Day, week (default), month and agenda (list) views with per-calendar colors, an hour grid with a current-time line, an all-day lane, overlapping events side by side, and infinite scrolling over time. Calendars and whole accounts can be shown or hidden (remembered). Keys: T today, J/K or arrows, D/W/M/A views, / search, N new event, Delete, Cmd+Z undo, Cmd+J join the next meeting.
- Editing in the app without the agent's approval card (the agent's own edits still ask): create by dragging on the grid or by double click, move by dragging (also to another day), resize by the top or bottom edge with 15-minute snapping, a detail panel (title, time, all-day, time zone, calendar, location, link, notes, alerts, recurrence, guests as read-only), "só este / este e os próximos / todos" for recurring events, undo of the last changes, read-only calendars respected.
- Quick create in Portuguese and English: "almoço amanhã 13h por 1h", "reunião sexta 10-11 no calendário Trabalho", "lunch tomorrow at 1pm for 1 hour", relative times, `#calendar`, `@ place`.
- Meetings: Meet, Zoom, Teams, Webex, Slack huddle and FaceTime links are found in the event URL, location or notes with an "Entrar" button; a notification a minute before (configurable) with an "Entrar" action; a menu bar item with the next meeting and a countdown; "Gravar e transcrever" starts the meeting recording named after the event and links the recording folder to it.
- Time zones: extra time columns (several allowed) and a time zone picker per event. Availability mode: mark free slots on the grid or generate them from working hours and your events, and copy them as text in pt-BR or English. A public booking link is not part of it.
- Brain: "Criar nota da reunião" writes `meetings/YYYY-MM-DD-HHhMMm-<title>.md` in the brain and puts `[[note]]` in the event notes; `[[note]]` links in events open in Obsidian. Search by title, location and notes; a side list of today's and late Reminders with check-off.
- Access and sync: a card with one button when Calendar access is missing, a hint to add a Google account in System Settings > Internet Accounts, and live refresh when the Calendar database changes.
- Brain tab: read, edit and organize the whole brain inside Wisp, without Obsidian. A file tree (folders first, expand and collapse, new note and folder, rename or move by dialog or drag, delete to the Trash) sits next to a note view with rendered Markdown: clickable `[[wikilinks]]` (file name, alias, `#heading`, `|text`, resolved like the brain index), muted unresolved links that offer to create the note, task checkboxes that write the file, tables, callouts, highlights, tags, footnotes, images, and `![[note]]` embeds that render inline and collapse. Drawing embeds (`.excalidraw`, `.canvas`) show a placeholder with "Abrir no app" until the drawing component lands. Frontmatter appears as an editable properties block that rewrites only the key you change.
- Renaming or moving a note or folder updates every `[[link]]` that reaches it (aliases, headings, relative paths, embeds and frontmatter links; code blocks are left alone), shows how many links change first, and applies all of it or none. Undo is the brain's git history.
- Source editor with Markdown highlighting, `[[` completion over titles and aliases, `#` tag completion, Cmd+E to switch between reading and editing, autosave with atomic writes, and change detection: a note changed by git, another editor or the agent reloads silently, or opens a merge prompt (merge, use the disk version, keep mine) when you have unsaved edits; whatever is discarded is first saved under Application Support/Wisp/brain-recuperado.
- Cmd+O quick switcher (title, alias, path), Cmd+Shift+F full-text search with snippets (`wisp brain search`, the same ranking as `brain_search`), back and forward, tabs, bookmarks (`brain-bookmarks.json` in the Wisp folder), the Brain tab's side panels (backlinks with context lines, links, outline, tags), today's daily note and template insertion following the brain's own `.obsidian/daily-notes.json` and `templates.json` (read-only) or the folder and date format the brain already uses, and "Perguntar ao Wisp sobre esta nota", which sends the note as context of the current conversation.
- `wisp brain search <query> [--root <folder>] [--limit N]` prints the ranked notes as JSON.

- Drawings: `BrainDrawingView(url:)` opens Obsidian Excalidraw drawings (`.excalidraw.md`, compressed or plain, and plain `.excalidraw`) and JSON Canvas files (`.canvas`). The Excalidraw editor ships inside the app and runs offline in a web view with a strict content security policy (no remote origin); the interface is in Portuguese. View and edit modes, autosave, reload when the file changes on disk (a prompt when you have unsaved edits), export to PNG and SVG, and `[[note]]` links inside drawings that open the note.
- Drawings keep the plugin's file format: frontmatter, the "Text Elements" section (regenerated with ` ^id` anchors, raw wikilinks kept), Element Links, Embedded Files and everything after the drawing are preserved, the drawing stays compressed or plain as it was, and writes are atomic, so the files stay openable in Obsidian. New drawings are created in the folder and with the name pattern of the Excalidraw plugin's settings.
- Drawings are flushed when the tab closes and when Wisp quits (up to 3 seconds), and a file whose text was not changed comes back byte for byte.
- Quitting while a drawing tab is still closing waits for its last save, and a drawing whose editor does not answer the save request warns instead of failing silently; loose paragraphs next to a deleted text element are kept.
- Canvas: native viewer and editor (pan, zoom, text, note, link and group nodes, edges with labels, move, resize, connect, delete) that round-trips the file byte for byte when untouched.
