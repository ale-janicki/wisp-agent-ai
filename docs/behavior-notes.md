# Behavior notes

Traps, invariants and external-system quirks that used to live as code comments. Grouped by module.

## core / Blocks

- `TaskList`: the "feito" key is the exact line (without newline) plus its occurrence index, so two identical lines stay distinct. The occurrence is counted over every line, the same way `deleting` counts. When the removed line was the last one and had no newline, the line before it keeps its own newline. Splitting is on "\n" only (Foundation literal search, not `split`): Swift reads "\r\n" as one Character that never equals "\n", and rejoining with "\n" must give the same bytes.
- `CommandTemplate`: each value is passed as one single-quoted shell word (`it's` -> `'it'\''s'`), so a key with spaces or quotes cannot split or inject.
- `BlockCommand`: runs through `zsh -c` with the login shell's PATH (a GUI app inherits a minimal one); blocking, call off main. The shell leads its own process group so a timeout signals it and everything it started (SIGTERM, then SIGKILL shortly after; always reaped). The parent closes its copies of the child's pipe ends, or the readers never see EOF. Both pipes are drained while the process runs, so a large output cannot stall it; after exit it waits at most a second for readers (a background child may hold the pipe).
- `AlertList`: `nivel` is `red` or `yellow` (anything else reads as yellow); open time is `aberto_ts`, else `ts`; red first, then newest. Dates accept ISO 8601 with or without fractional seconds and `Z` or `-03:00` / `+0530` offsets.
- `AgendaList`: `allDay` events carry dates, not times; a `declined` response is excluded from now / next / count; all-day first, then by start.

## core / Settings

- `HexColor`: `#RRGGBB` only; the 3-digit shorthand is rejected, not expanded.
- `WispSettings`: a custom theme picks accent, background and surface; the rest is derived. If the default text does not reach WCAG AA contrast (4.5) over a custom background, the side with better luminance is used. Saved tile order is always a permutation of `DashboardTileID.defaultOrder` (unknown ids and repeats dropped, missing appended). Files written before `dashboardOrder` existed decode to the default order. An unknown preset id (or "custom" without colors) falls back to the default lime.
- `SettingsStore`, `ConversationStore`, `ClipboardStore`: written atomically; a corrupt file is moved to `<name>.bad` (a second corruption overwrites the older `.bad`) and defaults are used; the move is reported through the store's recovery note.

## core / Memory, Routines, Profile

- `MemorySearch`: the search template fills `{query}` / `{root}` with shell-quoted values and must print `path<NUL>line:text` (grep/rg `--null -n`) or `path:line:text` (the first `:<digits>:` ends the path). BSD grep does not descend into a symlinked root (the owner's vault links into iCloud Drive), so commands get the symlink-resolved path. Obsidian names a vault after its folder; the `obsidian://open` URL percent-encodes every reserved character in both values, `/` included. Title matches sort first, else command order.
- `Routines`: `launchctl print` exits 113 ("Could not find service") for a label that is not loaded. Only the job's own top-level keys (one tab deep) are read; nested blocks such as the resource coalition repeat `state = active` and are ignored. Log tails read at most `maxBytes` from the end and drop a partial first line; "\r\n" is one Character in Swift, so it is a separator of its own.
- `Profile`: a `blocks` value of an unknown shape is ignored instead of failing the whole profile; a block with no command is a hidden tab.

## core / Spotify

- `SpotifyAuth`: PKCE verifier is 48 random bytes, base64url without padding (64 characters; RFC 7636 allows 43-128). The redirect is the loopback IP literal `127.0.0.1`: Spotify rejects `localhost` and allows plain HTTP only for loopback literals. A refresh response may omit `refresh_token`; then the previous one stays valid.
- `SpotifyModels`, `SpotifyRequests`: Feb 2026 API changes: a playlist's `tracks` became `items` (`tracks` kept as a deprecated fallback) and a playlist row's `track` became `item`; dev-mode `GET /search` allows at most 10 per type. An element that is `null` or undecodable decodes to nil so one bad item never drops a page. Episodes carry their own images instead of an album. Player 404 = no active device; player 403 with `PREMIUM_REQUIRED` (or a "premium" message) = not a Premium account. The play target is the active device, else this computer, else any controllable one.

## core / Memory graph

- `LinkGraph`: links resolve like Obsidian: by basename, case-insensitive, shortest path first; an unresolved link becomes a ghost node, except attachment extensions (never ghosts). Edges are undirected and de-duplicated, stored with `a < b`. Code fences and inline code are ignored when extracting links. The scan caches link targets by mtime and size; iCloud files not downloaded (`SF_DATALESS` flag, or legacy `.name.md.icloud`) are never read, since reading would block on a download. The base path goes through `realpath` so it matches the `/private/var/...` form the enumerator yields.
- `GraphLayout`: d3-force model with Barnes-Hut repulsion. Cooling is 300 steps from alpha 1; when most positions come from the cache it starts lower and settles in about 100. Seeding indexes each source once (O(N)); the layout on screen wins over the one on disk. Nodes without a seed start beside a seeded neighbour, else on a phyllotaxis spiral. A drag holds alpha at 0.3 (d3 `alphaTarget`); link strength is d3's `1 / min(degree)` times a multiplier; collision is one d3 forceCollide iteration, unscaled by alpha, on a grid of cells two max-radii wide. Panel values out of range clamp, missing ones default.

## core / Agent, Store, Telegram

- `AgentSession`: decoding under the lock keeps yields in stream order across handler invocations. Orphaned grandchildren can hold the pipes open, so the exit is emitted once the process is gone anyway.
- `ClaudeLocator`: the login-shell PATH is computed once per process.
- `ConversationReducer`: pure state machine over session events; when the session is gone, no queued turn can still produce a result.
- `TranscriptReader`: incremental, a line is read only once its newline lands. The project folder name is the cwd with every character outside `[A-Za-z0-9]` replaced by "-", one per Unicode scalar (same as the bot's `sessao.slug`). The CLI writes one line per content block. Injected prompts (slash commands, local command output, reminders), interrupt placeholders and the bot's own follow-up turn are not part of the conversation; when the session moved machine the bot wraps the user's message in context and the message follows a marker.
- `TranscriptFollower`: state is touched on its queue only. A missing file is a real state (a topic before its first turn): reported once, empty. On change the next poll reopens whatever sits at the path; a replaced file is read again from the start with a fresh parser. The descriptor outlives the dispatch source, never the reverse.
- `TelegramHTML`: `&amp;` is unescaped last so `&amp;lt;` becomes `&lt;`, not `<`.
- `TelegramTopics`: the bot is the only process that runs `claude` on a topic's session; Wisp reads the transcript and talks through `blocks.telegram.send`. `reading` comes from the status `reader`: `.here` (this machine's bot reads), `.elsewhere(host)` (the other machine reads; `Wisp-topico` routes create/send/close to that host's control queue over ssh, so its bot runs the turn), `.nobody`. Without a `reader` field, `up` alone decides (older CLI). When the PC reads, the reply reaches this disk only through the Mac bot's mirror (`sessao.espelhar_do_pc`, every 60 s, and not again within 120 s of its last copy), so the reply shows up to a few minutes late; the follower rereads the replaced file from the start. The topic list is the brain notes with status active plus the reading bot's `topics.json` (a topic born on the other machine has no note here yet); when the PC reads and its `topics.json` cannot be read, the list command fails instead of returning a partial list. A partial `blocks.telegram` counts as no Telegram. `topics == nil` (never read) keeps every conversation in Wisp.

## core / Usage, System, Media, Clipboard, Shell

- `UsageAggregator`: only files modified inside the window are opened, streamed line by line; each `message.id` counts once; a cheap byte check skips lines without usage. Cache reads are reported apart from the turn's spend.
- `PlanLimits`: Wisp never reads the OAuth token nor calls the usage API; limits come from the statusline's `rate-limits.json` or the CLI's `rate_limit_event`, newest wins. A window whose reset time passed is stale.
- `UsageFormat`, `SystemFormat`: a value that rounds up to 1000 carries into the next unit ("999,96 GB" -> next unit, not "1000 GB"). Disk and network use decimal units (Finder), memory binary (Activity Monitor).
- `CPUUsage`, `NetworkRate`: counters are 32-bit and wrap; deltas are taken modulo 2^32. Nil when the CPU count changed or no time elapsed.
- `TemperatureSummary`: `PMU* tdie*` are SoC die sensors (Apple does not say which die is CPU or GPU), `NAND*` the SSD, `gas gauge battery` the battery; implausible values (`tdev` sensors report about -22 C idle) are dropped.
- `ProcessTable`: `ps` is setuid and sees every user's processes, `proc_pidinfo` only ours; `%cpu` may be above 100 and may use a comma decimal; `comm` may contain spaces.
- `VolumeUsage`: `available` is `volumeAvailableCapacityForImportantUsage` (Finder, purgeable counted as free); `availableRaw` is `volumeAvailableCapacity`.
- `MemoryBreakdown`: App = anonymous minus purgeable; Used = App + Wired + Compressed; Cached = file-backed + purgeable. Pressure level values are the kernel's: 1 normal, 2 warning, 4 critical.
- `NowPlayingParser`: fields are joined by U+001F; AppleScript writes reals with the locale's decimal separator ("12,5" in pt-BR).
- `ClipboardHistory`: items carrying an nspasteboard.org concealed / transient marker (including older markers some apps still write) are never stored; copying the same content again moves the entry up keeping its pin; pinned items are never evicted; big text copies are not recorded.
- `NotchGeometry`: the band hugging the notch never changes between rest and active; active only adds a strip below it.

## app

- `NowPlayingService`: every script is wrapped in `is running`, so a player that quit between the check and the script is never relaunched by `tell`. `AEDeterminePermissionToAutomateTarget` blocks (with `ask` it waits on the system prompt): it runs on its own queue, never main, and a prompting request has its own queue so an unanswered prompt does not hold back the other player's checks. No query at launch, so the Automation prompt never appears out of context; only a player that already granted Automation is queried; the prompt comes from "Permitir controle". A grant is cached (the 1 s ticker must not hit tccd); a revoke surfaces as -1743. The wildcard permission check does not prompt, a real harmless Apple Event does. Local files and ads have no artwork URL; that must not hide the track.
- `ShellController`: window-server routing ignores `hitTest`, so outside the pill the window stops taking events outright; the global monitor keeps firing and flips it back when the cursor enters. Hover-open never steals the keyboard. Leaving `.panel`, a window that stays key keeps eating keystrokes, so it is cycled out of the window list and focus returns to the previous app only if the user did not switch apps meanwhile. Frames jump (not slide) across displays. `CGRect.contains` excludes the max edges; the cursor can sit exactly on the top edge.
- `PillView`: an always-on 30 fps timeline in the resting pill cost 6-12% CPU, so it animates only while busy. The pill sits in a top-aligned centered overlay so its fixed size never feeds back into the hosting view's window size.
- `ComposerView`: corner radius is half the one-line height; `.continuous` at that radius left a half-filled 1pt column at the leading edge. The AppKit layout callback is deferred because it may run inside a SwiftUI update.
- `SettingsView`: the color panel must float above the notch panel or it opens hidden behind it.
- `SidebarView`: the Cmd-N shortcut button uses `.opacity(0)`; `.hidden()` would drop the shortcut.
- `AppSettings`: writes go through one queue (ordered); a color picker drag is debounced; flush on terminate so a change inside the window is not lost.
- `TelegramModel`: a failed list read keeps the last list (a missing topic would hand its session to local `claude`); a topic closed from Wisp is hidden at once, since its note may say active until the next brain sync. When the other machine reads and the profile has `blocks.telegram.claim`, every create and send first runs the claim (`Wisp-topico assumir`, 75 s cap) with "Trazendo a conversa do <host>…" in the conversation: the claim makes this machine the reader (the other one yields only after its running turn ends) and pulls the topic's session here, so the turn runs on this machine and the reply lands on this disk without the mirror. A failed claim shows its sentence and the message is not sent. The claim also runs, silently and with no step, when this machine already reads but `status --json` says the last claim is not this machine's (`claim` other host, "none" or unknown): otherwise the other machine would take the reader back when its bot or the machine comes up mid-conversation. With the PC offline the Mac's claim stays pending in the Mac bot, which delivers it on its first check after the PC comes back, and status then reports the claim as the Mac's, so later sends skip it. `claim` is optional: without it the block still counts as complete and sends go to the other machine's queue as before.
- `TabModels`, `DashboardModels`, `MemoryModel`, `RoutinesModel`, `TelegramModel`: live for the process (the panel view is rebuilt on every open) and never act as source: every read goes back to the profile's file or command, the newest read wins, and a forced read during a running one runs again after it (the running read may predate an action). The agenda command hits the network, so non-forced refreshes within `maxAge` keep the last result.
- `ConversationViewModel`: a conversation linked to a topic stays the bot's unless a read topic list says the topic is gone; an unknown list (never read, bot down) must never let Wisp run `claude` on the bot's session. Session starts are serialized (one start at a time, the next waits for the stop) so two children never share one transcript; a start in flight notices a new generation and stops its own child. The pill reacts only to a result or phase change; `result` is the sole path that shows a reply in the pill.
- `ClipboardService`: whatever sits on the pasteboard at launch is not recorded; with capture off a change is counted but never read, so turning capture on does not record what was copied meanwhile; Wisp's own write-back is not re-recorded.
- `SystemProbe`: IOHID temperature symbols are private (not in headers), resolved with `dlsym`; any missing symbol leaves sensors unavailable (nil). `kIOHIDEventTypeTemperature` = 15. When no sensor is readable the UI shows the system thermal state, never an invented number.
- `HomeDashboard`: drag starts after `dragThreshold` pt so clicks inside the card keep working; bubbles are whole only (newest 3, else 2, else 1).
- `SnapshotRenderer`: uses an offscreen `NSHostingView` + `cacheDisplay` because `ImageRenderer` draws ScrollView content empty and AppKit-backed views as placeholders; no Screen Recording permission needed. Debug launch arguments: `-WispSnapshot <dir>`, `-WispTelegramE2E` (posts in the owner's Telegram), `-WispFrameLog <file>`, `-WispDemoAsk "<text>"`, `-WispDemoAsk2`, `-WispDemoRetry`.
- `Spotify` (app): the session lives only in the login Keychain, never in a file or a log. Token refresh is single flight (concurrent callers share one request) and 429 waits out `Retry-After`. The loopback listener touches its state only on its queue and returns once the socket is bound, so the browser opens only when the redirect can land; its handlers are held strongly on purpose and `finish` clears them to break the cycle. A generation counter bumps on every connect and sign-out: a login finishing after a sign-out drops the tokens it just stored. A player command with no active device retries once on the best available one.
- `MemoryGraphModel`: edge strokes are built off main in chunks of 16 segments (one 12k-segment path took 74 s to rasterize in software, chunks about 60 ms); while a layout is still settling with the same nodes and edges, the old strokes stay on screen until the rebuilt ones land. Re-entry within 30 s is a no-op; the scan is incremental after the first. The canvas reads the properties it depends on inside the draw closure so Observation re-renders it. A drag is refused while no input view is on screen (nothing could deliver its mouse-up) and is abandoned (node unpinned, hover cleared) when the view leaves its window, the panel closes, or the tab, mode or scene changes. A new canvas size reframes at once while the camera is fitting. `GraphSimulator`: leaves keep a minimum on-screen radius, so node paths are rebuilt per zoom bucket (zoom rounded to an eighth of an octave, about every 9%). `MemoryGraphView` input view: SwiftUI may insert the replacement view before removing the old one, so the display-link hook is dropped only if it is still ours. Frame intervals log under category `graphperf` (`log show --predicate 'subsystem == "com.owner.wisp" && category == "graphperf"' --last 5m`; a burst ends after 0.7 s idle). `-WispGraphBench` measures on the real on-screen window: using the panel mid-run, display sleep or the lock screen detaches or occludes the view and stops the display link, so the bench logs "aborted" instead of numbers for a graph nobody sees. The snapshot frame probe forces synchronous renders (a software upper bound).
- `ArtworkCache`: one fetch per key, LRU-capped; a failed URL is not fetched again for `failureMemory`.
- `wisp setup harness`: every decision is computed in memory first; the backup and the writes happen only when something would change, so a second run writes nothing and makes no backup. `~/.claude`, `CLAUDE.md`, `settings.json` or `agents|skills|commands` being a symlink (or a symlink anywhere in an installed file's path) stops the step before any write: writing would go through the link into a harness the user manages elsewhere. A file we installed is updated only while its bytes still equal the sha256 recorded in `~/.config/wisp/harness-installed.json`; any other difference is the user's edit and is kept. A missing or unreadable manifest therefore turns every differing file into a conflict, never into an overwrite. The backup copies symlinks as links. `settings.json` is rewritten with 2-space indent only when the merge changes it. `force_merge` is accepted and not used yet.

## bot

- `config`: the bot reads the same `wisp.json` as the CLI (`WISP_CONFIG`, else `$XDG_CONFIG_HOME` or `~/.config` + `wisp/wisp.json`) and never imports `wisp`. The module constants (`store.STORE`, `ctl.DIR`, `abrir.FILA`, `vigia.ARQUIVO`, `hosting.DIR`, `topicos.BRAIN/DIR/REL`) come from a lenient read at import that never opens the token file: no file or a broken one gives the defaults (`solo`, `~/Wisp/brain`, `~/.local/state/wisp/bot`, user 0 = nobody is answered). `wisp-bot` then runs the strict read and refuses to start with one sentence naming the key (`user_id`, `chat_id`, `token_file`, `hosting`, `pair`). The token comes only from `telegram.token_file`, never from the environment. The persona is the top-level `persona` only (the CLI no longer writes a telegram copy that would always say the default). In `pair` the strict read also requires `telegram.pair.user` and `telegram.pair.pc_name`. `telegram.system_topics` (`{"<thread>": "<name>"}`) is read by the bot only; the CLI's `TelegramConfig` does not keep it yet, so a CLI re-save drops it. A process that changes `WISP_CONFIG` must import `wisp_bot` after setting it.
- `hosting`: `solo` (the default) never runs ssh: `pc_argv()` returns None, `Hosting.rodar` activates the reader once, retries every `BATIDA_S` when activation failed (network) or after a 409 block, and publishes `host-state.json` every beat. `pair` is the Mac<->PC code as it was; `telegram.pair` gives `config` (KEY=VALUE file with PC_HOST, PC_LAN_IP, PC_USER, PC_USER_LINUX, PC_TS_NAME), `ssh_key`, `pc_name` (tailnet node), `user` and `state_rel`. The scripts sent to the PC use `$HOME/<state_rel>`; without `state_rel` it is this host's `state_dir` relative to its home, so a `state_dir` of `~/.Wisp-telegram` produces the same scripts as the old bot. A `state_rel` that is not a plain relative path is refused by the strict read and replaced by the default at import.
- `hosting` 409: in `solo` on Linux (`HOST == "pc"`) a 409 Conflict never releases the reader, as the PC did in the copied bot; on a Mac the reader backs off for `CONFLITO_BLOQUEIO_S` and `_rodar_solo` takes it again after the block. Two processes with one token on Linux therefore keep trading 409s until one stops.
- Leaving a topic for the terminal: in `solo` only `terminal-<this host>` is a destination (`ctl.destinos()`); "terminal pc" on a Mac answers that there is one machine. The goodbye message gives `claude --resume <sid>` in `solo` and `wisp topic puxar <thread>` in `pair`, where the session may have to come from the other machine first.
- `ctl`: the protocol is unchanged: `<state_dir>/ctl/<id>.json` holds `{id, op, ...args, at}` and `done/<id>.json` the result. Keys per op as the topic CLI writes them: `falar {thread, texto, origem}`, `encerrar {thread}`, `vincular {session_id, nome, cwd}`, `desvincular {session_id}` (`test_ctl_request_shape_unchanged`).
- `brain_sync_cmd` / `alert_cmd`: argv lists (a string is split like a shell); the verb (`pull`/`push`) or the alert args (`add --nivel red --chave K --frente bot TEXT`, `resolve K`) are appended. Without the command the sync is a successful no-op and the alert a no-op that returns False.
- Environment: tuning knobs keep their names with the `WISP_` prefix (`WISP_GRACE_S`, `WISP_MODEL`, `WISP_HOST`, ...). Turns get `WISP_SKIP_PULL=1` and, in a task topic, `WISP_TOPIC_NOTE`, `WISP_TOPIC_BASE`, `WISP_TOPIC_THREAD`: a harness hook that read the old `Wisp_TOPIC_*` names must read these. The bot's prompts wrap the user's message after `Mensagem do usuario:\n`; a CLI that extracts the message from a transcript must split on that marker.
- Removed against the copied bot: the e-mail, job-alert, market-journal and abrupt-power-loss integrations, the brain-digest context, the WSL `/dev` and `/jogo` commands and their tests. The tests that exercised the old harness's topic CLI and hooks went too (the CLI port carries its own). Fixtures are real session transcripts reduced to what the detector reads (event types, timestamps, ids, tool names, notification tags, `run_in_background`, the cut-off marker): every other text is a placeholder.

- `wisp topic`: `falar` has no `--anexo` yet (the copied bot's `falar` op does not read `anexos`; a flag the bot ignores would drop files silently). `puxar` has no NAS fallback: a session missing from both machines is an error sentence. In `solo`, `assumir` skips the bot-alive check and `puxar` answers that the session is already here.
