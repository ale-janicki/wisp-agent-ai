# Behavior notes

Developer notes: traps, invariants and external-system quirks, grouped by module.

## core / Blocks

- `TaskList`: the "feito" key is the exact line (without newline) plus its occurrence index, so two identical lines stay distinct. The occurrence is counted over every line, the same way `deleting` counts. When the removed line was the last one and had no newline, the line before it keeps its own newline. Splitting is on "\n" only (Foundation literal search, not `split`): Swift reads "\r\n" as one Character that never equals "\n", and rejoining with "\n" must give the same bytes.
- `CommandTemplate`: each value is passed as one single-quoted shell word (`it's` -> `'it'\''s'`), so a key with spaces or quotes cannot split or inject.
- `BlockCommand`: runs through `zsh -c` with the login shell's PATH (a GUI app inherits a minimal one); blocking, call off main. The shell leads its own process group so a timeout signals it and everything it started (SIGTERM, then SIGKILL shortly after; always reaped). The parent closes its copies of the child's pipe ends, or the readers never see EOF. Both pipes are drained while the process runs, so a large output cannot stall it; after exit it waits at most a second for readers (a background child may hold the pipe).
- `AlertList`: `nivel` is `red` or `yellow` (anything else reads as yellow); open time is `aberto_ts`, else `ts`; red first, then newest. Dates accept ISO 8601 with or without fractional seconds and `Z` or `-03:00` / `+0530` offsets.
- `AgendaList`: `allDay` events carry dates, not times; a `declined` response is excluded from now / next / count; all-day first, then by start.

## core / Agenda (native Calendar and Reminders)

- `AgendaService` runs over the `AgendaStore` protocol (`EventKitStore` in production, a fake in tests); `wisp-agenda` is only its `main`. Output is JSON on stdout; an error is one pt-BR line on stderr: exit 1 generic, 2 permission, 3 needs the user's confirmation (event with guests).
- Permission: denied, restricted and write-only read as "no access" (the message says "ler" for reads and "alterar" for create/edit/delete/complete; write-only says Wisp only has write access and needs full access) and are never asked again (the error names Ajustes do Sistema > Privacidade e Segurança); only `notDetermined` asks (the one system prompt), waiting at most 60 s: past that it exits 2 with "abra o Wisp no Mac e permita a agenda em Ajustes > Agenda". `calendarios` still lists the kind that was granted. `permissao` prints `{"eventos": state, "lembretes": state}` without asking; `permissao --pedir` asks for the undetermined ones. Ajustes > Agenda ("Agenda: permitir acesso") runs the embedded helper this way from the app process, so the prompt is attributed to Wisp; a helper started by the Telegram bot (launchd) may need that grant done once from the app first. Both Info.plists carry the usage strings and both signatures carry `com.apple.security.personal-information.calendars` (the helper target also sets `CODE_SIGN_ENTITLEMENTS`, so Debug and local builds have it). Not verified on a real prompt.
- Recurring events: `eventos` prints `"recorrente": true` and an occurrence id `<eventIdentifier>@<start ISO>`; the store finds that occurrence by searching one day around the start and matching the identifier and the start to the second, then uses `.thisEvent`. Edit or delete of a recurring event by its bare id is refused; `--serie` is explicit and uses `.futureEvents` (that occurrence and the next ones, "esta e as próximas"; never the past ones, so not the whole series). A bare id that ends in `@something` that is not a date-time (Google ids) stays whole.
- Edit and delete of an event with guests need `--confirmo` (exit 3 otherwise); it is a convention the agent must only pass after the user said yes, not enforcement. Edit also checks the final end against the final start (all-day events may be equal).
- Limits: `eventos` ranges are clamped to 92 days and cut at 200 items, and the output is `{"events": [...], "truncado": bool}`; `lembretes` without `--pendentes` returns pending ones plus those completed in the last 30 days (completed with no date are left out).
- Ranges: `--hoje` is today 00:00 to tomorrow 00:00 (local zone); `--semana` and the default are the next 7 days from today 00:00; a date-only `--ate` includes that whole day; no `--ate` means 7 days after `--de`. Output times are ISO 8601 with the local offset; an all-day event prints dates (`yyyy-MM-dd`) with an inclusive end, as EventKit stores it.
- Input times accept ISO with offset (`-03:00` or `-0300`), `yyyy-MM-ddTHH:mm[:ss]` or `yyyy-MM-dd HH:mm` (local zone) and `yyyy-MM-dd` (date only). An event whose start and end are both date-only is all-day; a reminder with a date-only `--quando` has a due date without time.
- Calendar and list names match case- and accent-insensitively; an unknown or ambiguous name errors with the options, a read-only calendar refuses writes.
- Event ids are EventKit's `eventIdentifier`: a recurring event keeps one id for the whole series, and edit and delete use `.thisEvent`, so they touch the occurrence EventKit resolves for that id. Reminder ids are `calendarItemIdentifier`.
- `wisp agenda` (Python) forwards its arguments untouched to the helper: `$WISP_AGENDA_BIN`, else `/Applications/Wisp.app/Contents/Helpers/wisp-agenda`, else `~/Applications/Wisp.app/...`. The runtime lives in `~/.local/share/wisp/runtime`, outside the app, so the app is found by those paths; the app sets `WISP_AGENDA_BIN` from `Bundle.main` in the agent's environment, so any install location works for it; if `WISP_AGENDA_BIN` is set but the file is missing, the command errors instead of trying the other paths. A helper killed by a signal returns exit 1 with a pt-BR line, never a negative code.

## core / Settings

- `HexColor`: `#RRGGBB` only; the 3-digit shorthand is rejected, not expanded.
- `WispSettings`: a custom theme picks accent, background and surface; the rest is derived. If the default text does not reach WCAG AA contrast (4.5) over a custom background, the side with better luminance is used. Saved tile order is always a permutation of `DashboardTileID.defaultOrder` (unknown ids and repeats dropped, missing appended). Files written before `dashboardOrder` existed decode to the default order. An unknown preset id (or "custom" without colors) falls back to the default lime.
- `WispSettings.settingsSection`: the Ajustes tab last opened; nil or an unknown id opens the first one (Aparência).
- `SettingsStore`, `ConversationStore`, `ClipboardStore`: written atomically; a corrupt file is moved to `<name>.bad` (a second corruption overwrites the older `.bad`) and defaults are used; the move is reported through the store's recovery note.

## app / Settings

- `IntegrationsPane`: one dropdown row per integration, one open at a time, all closed on arrival. `expandOnOpen` is a main-actor static set right before navigating to Ajustes > Integrações (the Música tab's "Abrir Ajustes") and cleared the first time the pane appears.
- `SpotifySettingsCard(embedded: true)`: inside an Integrações dropdown it has no title and no card of its own, since the host row already says "Spotify".
- `ToggleRow`: the whole row flips the switch (the switch itself ignores hits); an `accessory` before the switch keeps its own clicks.
- `TabSettings` (core): pure map from a `PanelTab` raw id to the Ajustes blocks that tab shows (`conversation` engine + model + permission mode, `brain` Brain, `agenda` Agenda, `meetings` Reuniões, `myMac` Controle do Mac, `music` Integrações) and to the Ajustes tab "Todos os ajustes" opens (`model`, `general`, `integrations`). Every other id has no blocks and no gear.
- Per-tab settings (app): the gear in the tab header (`TabSettingsButton`; Conversa header, Brain, Reuniões and Música card headers via `TabCard.settingsTab`, Agenda toolbar, My Mac header) swaps that tab's content for `TabSettingsPage` (state `PanelView.settingsTab`, one tab at a time, cleared when the tab changes): "Voltar" returns to the tab, "Todos os ajustes" saves the matching Ajustes section and switches to Ajustes. The page renders the same views Ajustes uses (`EngineSettingsCard`, `ModelPickerCard`, `PermissionSettingsCard`, `BrainSettingsGroup`, `AgendaSettingsGroup`, `MeetingsSettingsGroup`, `MacControlSettingsGroup`, `IntegrationsPane`), so bindings and persistence are shared and nothing is duplicated. The Agenda gear sits in the calendar toolbar, so it is absent while calendar access is not granted (the access card shows instead). Not verified at runtime.

## core / Memory, Routines, Profile

- `MemorySearch`: the search template fills `{query}` / `{root}` with shell-quoted values and must print `path<NUL>line:text` (grep/rg `--null -n`) or `path:line:text` (the first `:<digits>:` ends the path). BSD grep does not descend into a symlinked root (for example a vault linked into iCloud Drive), so commands get the symlink-resolved path. Obsidian names a vault after its folder; the `obsidian://open` URL percent-encodes every reserved character in both values, `/` included. Title matches sort first, else command order.
- `Routines`: `launchctl print` exits 113 ("Could not find service") for a label that is not loaded. Only the job's own top-level keys (one tab deep) are read; nested blocks such as the resource coalition repeat `state = active` and are ignored. Log tails read at most `maxBytes` from the end and drop a partial first line; "\r\n" is one Character in Swift, so it is a separator of its own.
- `Profile`: a `blocks` value of an unknown shape is ignored instead of failing the whole profile; a block with no command is a hidden tab.

## core / Spotify

- `SpotifyAuth`: PKCE verifier is 48 random bytes, base64url without padding (64 characters; RFC 7636 allows 43-128). The redirect is the loopback IP literal `127.0.0.1`: Spotify rejects `localhost` and allows plain HTTP only for loopback literals. A refresh response may omit `refresh_token`; then the previous one stays valid.
- `SpotifyModels`, `SpotifyRequests`: Feb 2026 API changes: a playlist's `tracks` became `items` (`tracks` kept as a deprecated fallback) and a playlist row's `track` became `item`; dev-mode `GET /search` allows at most 10 per type. An element that is `null` or undecodable decodes to nil so one bad item never drops a page. Episodes carry their own images instead of an album. Player 404 = no active device; player 403 with `PREMIUM_REQUIRED` (or a "premium" message) = not a Premium account. The play target is the active device, else this computer, else any controllable one.

## core / Memory graph

- `LinkGraph`: links resolve like Obsidian: by basename, case-insensitive, shortest path first; an unresolved link becomes a ghost node, except attachment extensions (never ghosts). Edges are undirected and de-duplicated, stored with `a < b`. Code fences and inline code are ignored when extracting links. The scan caches link targets by mtime and size; iCloud files not downloaded (`SF_DATALESS` flag, or legacy `.name.md.icloud`) are never read, since reading would block on a download. The base path goes through `realpath` so it matches the `/private/var/...` form the enumerator yields.
- `GraphLayout`: d3-force model with Barnes-Hut repulsion. Cooling is 300 steps from alpha 1; when most positions come from the cache it starts lower and settles in about 100. Seeding indexes each source once (O(N)); the layout on screen wins over the one on disk. Nodes without a seed start beside a seeded neighbour, else on a phyllotaxis spiral. A drag holds alpha at 0.3 (d3 `alphaTarget`); link strength is d3's `1 / min(degree)` times a multiplier; collision is one d3 forceCollide iteration, unscaled by alpha, on a grid of cells two max-radii wide. Panel values out of range clamp, missing ones default.

## core / Agent, Store, Telegram

- `AgentSession`: decoding under the lock keeps yields in stream order across handler invocations. Orphaned grandchildren can hold the pipes open, so the exit is emitted once the process is gone anyway.
- `ClaudeLocator`: the login-shell PATH is computed once per process.
- `ConversationReducer`: pure state machine over session events; when the session is gone, no queued turn can still produce a result.
- Permission prompts (confirmed against Claude Code 2.1.327 in a scratch folder, 18/11/2026): in `-p --input-format stream-json` a tool call that needs approval reaches the host only with `--permission-prompt-tool stdio`. Without it (`--permission-prompts` defaults to `host`, an `initialize` control request sent or not) the call is denied on the spot (`system/permission_denied`, `permission_decision.source: "config"`). No `initialize` is needed. The CLI writes `{"type":"control_request","request_id":R,"request":{"subtype":"can_use_tool","tool_name","display_name","input","description","permission_suggestions":[...],"blocked_path"?,"tool_use_id"}}` right after the assistant's `tool_use` and holds the call until the host writes one line on stdin: allow `{"type":"control_response","response":{"subtype":"success","request_id":R,"response":{"behavior":"allow","updatedInput":{...}}}}` (`updatedInput` may be left out in this version; Wisp echoes the input), "always" adds `"updatedPermissions":[suggestions]`, deny `{"behavior":"deny","message":M}`. Deny makes M the tool result (`is_error`, source `user_reject`) and Claude goes on; the tool still lands in the result's `permission_denials`, so the reducer drops the "libere em settings.json" hint for tools the user denied. Suggestions seen: `addRules` (`destination: "localSettings"`, i.e. `<cwd>/.claude/settings.local.json`; Bash `touch probe1 *`, WebFetch `domain:example.com`), `addDirectories` and `setMode acceptEdits` (both `session`). Sending all of them also switched the session to `acceptEdits` (a `system/status` line), so "Sempre permitir" sends only `addRules` with a non-session destination and shows only when there is one (Write offers none). `control_cancel_request` (drops a queued request) is handled but was not observed. Other `control_request` subtypes are ignored: Wisp registers no hooks or SDK MCP servers.
- Permission modes: `--permission-mode` accepts `default` (the help lists `manual`; init reports `default` for it), `auto`, `bypassPermissions`; the flag beats `permissions.defaultMode` in settings, and with no flag the CLI uses that setting. `auto` ran in `-p` on the owner's account (init `permissionMode: "auto"`, calls accepted with `reason_type: "mode"` or `"classifier"`; the classifier even accepted `rm -rf` of a sibling scratch folder). If the CLI reports another mode at init after Wisp asked for `auto`, the conversation says so and Ajustes shows Automático disabled for the rest of the run (how an account without `auto` behaves was not observed). `bypassPermissions` still runs `PreToolUse` hooks (a scratch hook exiting 2 blocked the call, `source: "hook"`) and `permissions.deny` rules (`reason_type: "rule"`), so the harness deny list and the secrets guard hold in every mode.
- Explicit `ask` rules in bypass (measured 20/11/2026, Claude Code 2.1.329): `claude -p --model haiku --input-format stream-json --output-format stream-json --verbose --permission-prompt-tool stdio --permission-mode bypassPermissions --settings '{"permissions":{"ask":["Bash(*aprender add*)"]}}'`, asked to run `./fakewisp aprender add "regra teste"`: init reported `permissionMode: bypassPermissions`, the CLI emitted a `control_request` `can_use_tool` for that Bash command, and the command did not run while the request stayed unanswered. So an `ask` rule with a leading `*` matches and prompts even in bypass. Without a prompt host (`-p` without `--permission-prompt-tool stdio`, as in the Telegram bot today) such a call is refused.
- `PermissionSetting`: Wisp's own setting (only set while the profile is a link) wins, then the profile's `agent.permissionMode`, then `permissions.defaultMode` from `~/.claude/settings.json` (or `$CLAUDE_CONFIG_DIR`), shown as "Definido no Claude" and never written. Unknown values count as unset. The profile is rewritten with sorted keys; a missing profile gets the persona/agent defaults the app needs to decode it.
- `TranscriptReader`: incremental, a line is read only once its newline lands. The project folder name is the cwd with every character outside `[A-Za-z0-9]` replaced by "-", one per Unicode scalar (same as the bot's `sessao.slug`). The CLI writes one line per content block. Injected prompts (slash commands, local command output, reminders), interrupt placeholders and the bot's own follow-up turn are not part of the conversation; when the session moved machine the bot wraps the user's message in context and the message follows a marker.
- `TranscriptFollower`: state is touched on its queue only. A missing file is a real state (a topic before its first turn): reported once, empty. On change the next poll reopens whatever sits at the path; a replaced file is read again from the start with a fresh parser. The descriptor outlives the dispatch source, never the reverse.
- `TelegramHTML`: `&amp;` is unescaped last so `&amp;lt;` becomes `&lt;`, not `<`. It also reads `br`, `blockquote` (`> `) and `strong`/`em`; Markdown code the model wrote (a fence or an inline span) is left as typed, so a `<b>` shown as code stays a literal. It runs once, when text enters the app: `ConversationReducer` (live `text` and `result`) and `TranscriptParser` (history, follower, previews), never again at render.
- `AgentInstructions`: the prompt (`--append-system-prompt`, `ClaudeCommand`) and env the app gives its `claude`. An app turn ALWAYS gets `appFiles` ("here" is the app: a file is a `[name](file:///abs/path)` Markdown link that opens on click; tested against `cli/tests/fixtures/contract/app-files-instruction.txt`), whatever else the conversation is. In a topic with a known wisp binary (`TelegramBlock.binary`, the unquoted `<bin>` of the `list` template; nil for a custom one) it appends `appSharedNote` (files linked here are sent to the topic automatically; only on an explicit ask for Telegram/the phone, `"$WISP_BIN" topic enviar --thread="$WISP_TOPIC_THREAD" FILE`) and sets `WISP_BIN` and `WISP_TOPIC_THREAD`. The bot's own turns get `telegramFiles` (= `TELEGRAM_FILES`, tested against `telegram-files-instruction.txt`): enviar to the topic. Both texts forbid calling the Telegram API directly and reading the bot token. After an app turn on a shared conversation, `FileLinks.absolutePaths` collects the `file://` links of the final assistant text (existing, readable, regular files, at most 10 and 50 MB each, outside the bot's deny-list folders, deduplicated) and the mirror passes them, plus the user's attachments, as `arquivos` of `telegram.post`, so the phone gets the file too. `TurnRestartPolicy` restarts a warm process whose topic differs from the conversation's current one (`contextChanged`), so a conversation unshared from Telegram stops carrying the bot's env.
- Closed conversations: the shared index (`conversations.json`) carries optional `closedAt` (ISO) and `closedFrom` ("telegram" for a close typed in Telegram, "app" for the control path used by the app and `wisp topic encerrar`); an index without them decodes as open. `bot.fechar` calls `conversa.encerrar_conversa` after the summary succeeded and the topic was dropped (a failed summary marks nothing); it finds the record by conversation id (case-insensitive) or `sessionId`, writes under `file_lock(index)` and `tmp.replace`, and never touches transcripts. `TelegramTopics.sections(allRecords:...)` is where Local and Telegram split: closed records are removed first (so a closed record never links to a topic), the rest go through `sections(records:...)`, and `closed` (newest close first) feeds the "Encerradas (N)" group. `ConversationStore` reloads when the file's modification date changed (the bot writes the index while the app runs) and `ConversationViewModel.save` keeps the stored `closedAt`/`closedFrom`, so a runtime persisting its own record never reopens a conversation. Reopening (`ConversationViewModel.reopen`) clears both fields in the Swift store and does not recreate the Telegram topic. `ConversationStore` takes an exclusive flock on `conversations.json.lock` (the bot's `file_lock`) around reload, merge and write in `upsert`, `delete` and `reopen`; `reopen(id:)` re-reads the stored record and clears only `closedAt`/`closedFrom`. A malformed `closedAt` decodes as open instead of sending the index to `.bad`.
- Old closed topics: `encerrar` writes the summary to the brain and the Telegram message, not to the transcript, so there is no "last line" marker to detect. The reliable signal is the topic note: `status: encerrado` plus its session pointer (`sessoes-<host>.json`) matching a record's `sessionId` while no live topic in `topics.json` has that session. `bot._migrar_encerradas` does this once in `_post_init` (guard file `encerradas-migradas` in the bot state dir), with `closedFrom` "telegram" and `closedAt` = the pointer's `session_last` (or now); a record whose `updatedAt` is later than that close time was used afterwards and stays open. It logs the count and ids closed. A topic closed from the terminal also reaches `encerrado`, so its conversation is closed too. Not verified against real data.
- `TelegramTopics`: one conversation = one Claude session; Mac only. The bot runs a topic's turns and the app runs the app's, each under the flock of `~/.local/state/wisp/locks/<session_id>.lock`, so two turns of one session never overlap. A section's conversation is the one whose id equals the topic's `conversation` (or, for a topic without one, whose `sessionId` equals the topic's `sessionId`); the app shows "Respondendo pelo Telegram…" while the lock is held elsewhere. Wisp reads the transcript and talks through the profile's `blocks.telegram` commands: `status`, `list`, `share`, `post`, `close` and optional `attachments`. A partial `blocks.telegram` counts as no Telegram. `topics == nil` (never read) keeps every conversation in Wisp. `reading` comes from the status `reader` and is always this Mac.
- `ClaudeCommand`: `--permission-prompt-tool stdio` sends every prompt to the host as a `can_use_tool` control request; without it a prompt in `-p` mode is denied on the spot. A variadic flag goes before another flag so that flag ends its list.
- `FileOpenPolicy`: a click on a `file://` link opens only known document types in the default app; everything that could run or install (programs, scripts, archives, installers, launchers, bundles, shortcuts, macro files, executables on disk, unknown types) is revealed in Finder instead. The decision uses the symlink-resolved path.
- `FileLinks` / `SentFiles`: the files a reply hands over are the `topic enviar` calls the agent made plus the reply's `file://` links, deduplicated by resolved path (a symlink, `..` or `~` spelling of one file is one file) and capped at `FileLinks.maxFiles`. The shell expands `~/` and `$HOME/` before `wisp` sees the path, so the parser mirrors that. Anything the bot would refuse (its denied folders, unreadable or over-limit files) is skipped; APFS ignores case, so `~/.SSH` is `~/.ssh` and the comparison is case-insensitive and by file identity where the path exists.
- `PhoneHandoff`: the message the topic gets on "Continuar no celular" quotes the last reply the user can read (the one before the streaming one while a turn runs), cut at a word with an unclosed code fence closed. A pending approval can only be answered on the Mac: the bot cannot reach the process that holds it.
- `RuntimeLifecycle`: idle runtimes with a live process beyond the `keepWarm` most recent, or unused for `idleTimeout`, lose their process (state stays, the next message resumes); the conversation on screen and any busy runtime are never returned, and busy ones do not count toward the cap. A runtime with nothing left to keep is dropped and rebuilt from the transcript. In the sidebar an approval waiting or an unseen reply (attention) outranks a running turn.
- `ConversationTitle`: the title is the first message cut at a word boundary until one `claude -p` call (cheapest model, no session file, no tool, hook, skill or MCP server) writes a real one; a failure or timeout keeps the cut, and a conversation reopened from a record never asks for one.

## core / Usage, System, Media, Clipboard, Shell

- `UsageAggregator`: only files modified inside the window are opened, streamed line by line; each `message.id` counts once; a cheap byte check skips lines without usage. Cache reads are reported apart from the turn's spend. `UsageIndex` keeps the parsed lines of each transcript between reads (a week is hundreds of MB; reading it all cost about 2 CPU-seconds each time Home opened). Transcripts are append-only JSONL: a file that grew is read from the byte just past the last newline read; one that shrank, is new, or kept its size with a different modification date is read whole (a rewrite to a longer file is indistinguishable from an append and is not detected). A last line with no newline yet is counted but read again next time. One lock guards the index; its only caller is the detached task of `UsageModel`.
- `PlanLimits`: Wisp never reads the OAuth token nor calls the usage API; limits come from the statusline's `rate-limits.json` or the CLI's `rate_limit_event`, newest wins. A window whose reset time passed is stale.
- `UsageFormat`, `SystemFormat`: a value that rounds up to 1000 carries into the next unit ("999,96 GB" -> next unit, not "1000 GB"). Disk and network use decimal units (Finder), memory binary (Activity Monitor).
- `CPUUsage`, `NetworkRate`: counters are 32-bit and wrap; deltas are taken modulo 2^32. Nil when the CPU count changed or no time elapsed.
- `TemperatureSummary`: `PMU* tdie*` are SoC die sensors (Apple does not say which die is CPU or GPU), `NAND*` the SSD, `gas gauge battery` the battery; implausible values (`tdev` sensors report about -22 C idle) are dropped.
- `ProcessTable`: `ps` is setuid and sees every user's processes, `proc_pidinfo` only ours; `%cpu` may be above 100 and may use a comma decimal; `comm` may contain spaces.
- `VolumeUsage`: `available` is `volumeAvailableCapacityForImportantUsage` (Finder, purgeable counted as free); `availableRaw` is `volumeAvailableCapacity`.
- `MemoryBreakdown`: App = anonymous minus purgeable; Used = App + Wired + Compressed; Cached = file-backed + purgeable. Pressure level values are the kernel's: 1 normal, 2 warning, 4 critical.
- `NowPlayingParser`: fields are joined by U+001F; AppleScript writes reals with the locale's decimal separator ("12,5" in pt-BR).
- `ClipboardHistory`: items carrying an nspasteboard.org concealed / transient marker (including older markers some apps still write) are never stored; copying the same content again moves the entry up keeping its pin; pinned items are never evicted; big text copies are not recorded.
- `NotchGeometry`: the band hugging the notch never changes between rest and active; active only adds a strip below it.

## core / Setup

- `CommandRunner` replaces the whole environment when one is given: for uv always pass `RuntimeBootstrap.processEnvironment(layout, base:)`, never `uvEnvironment` alone (PATH, HOME, proxies and SSL_* would be lost).
- Known gap: the runtime root is under `$HOME`; a home folder with a space is passed as separate argv/env values, but uv and the venv shebangs under such a path have not been run end to end.
- `SetupState` is read and written only through `SetupState.load/save` (ISO 8601 dates), so the setup screen and the gate agree. An existing install (a profile already there, or a re-run) never sees the setup: `SetupGate.shouldShowWizard` and `SetupFlow.persisted` are unchanged.
- Setup is one screen. `SetupOffer.make` builds the three cards from the hardware, the recommender result and the `wisp local catalog` status: the default engine is always IA local with the recommended model, and it becomes Claude (with the note "conecte em Ajustes") only when the Mac is not Apple silicon or no catalog model is enabled (memory "não cabe", or not enough free disk for one that is not on disk). Claude and Codex are never the default, even when logged in; "Conectado" comes from the doctor's `claude_login` / `codex_login` and is shown only on the selected card. A chosen model that is disabled falls back to the recommended one.
- Connecting Claude or Codex (`EngineLogin`, `EngineConnectFlow`, app `EngineConnectModel`/`EngineConnectBlock`, shown in the Motor card, so also in the Conversa tab settings): the button writes `wisp-connect-<engine>-<uuid>.command` (0700, in `<temp>/wisp-connect`, content = a `zsh -l` shebang, a constant PATH line and the fixed command `claude` or `codex login`, never from config or input) and opens it with `NSWorkspace.open(_:withApplicationAt:)` on `com.apple.Terminal`, which runs it. Terminal is not driven by Apple Events, so there is no Automation prompt and no new entitlement. Old `.command` files are deleted at launch (`AppDelegate`). The CLI is located first (`ClaudeLocator` / `CodexLocator`, off the main actor); missing = Terminal never opens and the card shows "Copiar comando" (Claude: `curl -fsSL https://claude.ai/install.sh | bash`) or "Veja como instalar" (Codex: its GitHub page). After opening, `wisp doctor --json --only claude_login|codex_login` is polled every 3 s for at most 10 min (200 polls) while the card is visible (SwiftUI `.task`, cancelled when the view goes away); `EngineConnectFlow` states are notInstalled, notConnected, waiting, connected, timedOut, and "Conectado" refreshes `EngineModel`. Not verified at runtime: Terminal, the real logins and the polling in the running app were not run.

## bot

- Continuar no celular (phone mode): one click shares the conversation if needed, posts "📱 Continuando aqui." with the last reply (about 800 chars) and whether a turn is running or an approval is pending, then sets `awayOnPhone` on the record. While it is on, the app's claude gets `--disallowedTools AskUserQuestion` and the sentence "The user is on the phone: ask any question as plain text at the end of your reply." (fixture `cli/tests/fixtures/contract/phone-instruction.txt`); the bot always passes that flag and sentence. A message sent from the app, or "Voltar ao Mac", turns it off with no Telegram post. The turn in flight when the user leaves still mirrors its reply. Approvals pending in the app can only be answered on the Mac. `wisp topic postar` with `user: ""` posts only the reply.
- `config`: the bot reads the same `wisp.json` as the CLI (`WISP_CONFIG`, else `$XDG_CONFIG_HOME` or `~/.config` + `wisp/wisp.json`) and never imports `wisp`. The module constants (`store.STORE`, `ctl.DIR`, `abrir.FILA`, `hosting.DIR`, `topicos.BRAIN/DIR/REL`) come from a lenient read at import that never opens the token file: no file or a broken one gives the defaults (`solo`, `~/Wisp/brain`, `~/.local/state/wisp/bot`, user 0 = nobody is answered). `wisp-bot` then runs the strict read and refuses to start with one sentence naming the key (`user_id`, `chat_id`, `token_file`, `hosting`, `pair`). The token comes only from `telegram.token_file`, never from the environment. The persona is the top-level `persona` only (the CLI no longer writes a telegram copy that would always say the default). In `pair` the strict read also requires `telegram.pair.user` and `telegram.pair.pc_name`. `telegram.system_topics` (`{"<thread>": "<name>"}`) is read by the bot only; the CLI's `TelegramConfig` does not keep it yet, so a CLI re-save drops it. A process that changes `WISP_CONFIG` must import `wisp_bot` after setting it.
- `hosting`: `solo` (the default) never runs ssh: `pc_argv()` returns None, `Hosting.rodar` activates the reader once, retries every `BATIDA_S` when activation failed (network) or after a 409 block, and publishes `host-state.json` every beat. `pair` hands Telegram reading between two machines; `telegram.pair` gives `config` (KEY=VALUE file with PC_HOST, PC_LAN_IP, PC_USER, PC_USER_LINUX, PC_TS_NAME), `ssh_key`, `pc_name` (the second machine's ssh host), `user` and `state_rel`. The scripts sent to the second machine use `$HOME/<state_rel>`; without `state_rel` it is this host's `state_dir` relative to its home. A `state_rel` that is not a plain relative path is refused by the strict read and replaced by the default at import.
- `hosting` 409: in `solo` on Linux (`HOST == "pc"`) a 409 Conflict never releases the reader; on a Mac the reader backs off for `CONFLITO_BLOQUEIO_S` and `_rodar_solo` takes it again after the block. Two processes with one token on Linux therefore keep trading 409s until one stops.
- Leaving a topic for the terminal: in `solo` only `terminal-<this host>` is a destination (`ctl.destinos()`); asking for the other machine's terminal answers that there is only one machine. The goodbye message gives `claude --resume <sid>`.
- `ctl`: `<state_dir>/ctl/<id>.json` holds `{id, op, ...args, at}` and `done/<id>.json` the result. Ops and keys as the topic CLI writes them: `encerrar {thread}`, `soltar {thread, destino}`, `compartilhar {session_id, cwd, nome}`, `postar {thread, user, reply, arquivos?}`, `enviar {thread, arquivos, legenda}`, `vincular {session_id, nome, cwd}`, `desvincular {session_id}`. There is no `falar`, `adotar` or `trazer`.
- `brain_sync_cmd` / `alert_cmd`: argv lists (a string is split like a shell); the verb (`pull`/`push`) or the alert args (`add --nivel red --chave K --frente bot TEXT`, `resolve K`) are appended. Without the command the sync is a successful no-op and the alert a no-op that returns False.
- Environment: tuning knobs keep their names with the `WISP_` prefix (`WISP_GRACE_S`, `WISP_MODEL`, `WISP_HOST`, ...). Turns get `WISP_SKIP_PULL=1`, `WISP_BIN` (the `wisp` CLI next to the bot's python) and `WISP_TOPIC_THREAD` (0 in Geral): the system prompt tells the agent to send files with `"$WISP_BIN" topic enviar --thread="$WISP_TOPIC_THREAD" <file>` (the bot validates: regular files, 10 max, 50 MB each, photo up to 10 MB else document, deny-list: the folders and file names of `cli/tests/fixtures/contract/send-denylist.json` (`.ssh`, `.gnupg`, `.aws`, Keychains, `.config/wisp`, `.kube`, `.docker`, gcloud, azure, gh, `.password-store`; names like `.env`, `.netrc`, `id_rsa*`, `*.pem`, `*.key`), matched on the resolved real path and case-insensitively, plus the token file; one retry on flood control). The bot's prompts wrap the user's message after `Mensagem do usuario:\n`; a CLI that extracts the message from a transcript must split on that marker.
- Test fixtures are real session transcripts reduced to what the detector reads (event types, timestamps, ids, tool names, notification tags, `run_in_background`, the cut-off marker); every other text is replaced.
- `wisp topic`: `status`, `listar`, `novo`, `compartilhar`, `postar`, `enviar`, `encerrar`. `puxar`, `assumir` and `falar` no longer exist; pulling an app conversation into Telegram is the bot's `/puxar` command.
- Command-line builds (`xcodebuild`) need `-skipPackagePluginValidation`: SwiftTerm ships a build-info plugin that Xcode's CLI refuses until it is trusted. `scripts/build-release.sh` passes it. - Claude installer (`setup_system`): the official `https://claude.ai/install.sh` is downloaded to `downloads/claude-install.sh` under the state dir with `curl --fail --proto '=https' --proto-redir '=https' --tlsv1.2`, run with `bash <file>` (never piped from the network) and the file is removed afterwards. - Secrets guard: `wisp hook guard-secrets` is a `PreToolUse` hook (Bash, Read, Edit, MultiEdit, Write, NotebookEdit, Grep, Glob) that exits 2 when any string of the tool input points into `<config dir>/secrets` (also `~/.config/wisp/secrets`). Paths are expanded (`~`, `$HOME`, `${HOME}`, `$XDG_CONFIG_HOME`), normalised (`..`, `//`, `./`), resolved against the call's cwd and through symlinks; Grep/Glob on the config dir itself is blocked too, as is `cd <config dir>` followed by a relative `secrets`. Limits: command substitution and variables set inside the command are not evaluated. The `permissions.deny` entries stay as a second layer.
- Telegram guard: `wisp hook guard-telegram` (`PreToolUse`, same tools as the secrets guard) is best-effort defense in depth, scoped to the Wisp bot only. It exits 2 with a one-line reason starting `wisp-guard:` (the only prefix the app treats as a guard block) when any tool names the Wisp config dir `~/.config/wisp/` (anything under it, `cd` into it, globs like `~/.config/wisp/*`; compared case-insensitively) or the Wisp token file (`telegram.token_file` of wisp.json, plus `secrets/telegram-token`), or when a Bash command or a Write/Edit/MultiEdit/NotebookEdit input loads the bot config for its token (`wisp_bot`/`load_bot_config`/`BotConfig` with `.token`), or names `api.telegram.org` next to a Wisp bot reference. Other bots may call the API with their own tokens, and `token_file` as a word (git messages, grep, jq on another json) is fine. Write/Edit/MultiEdit/NotebookEdit on a file inside a Wisp source checkout (a folder holding `bot/src/wisp_bot` and `cli/src/wisp`) only has its path checked. Limits: a script that builds a path or URL from pieces, a relative path reached after `cd` into a parent, or a file written elsewhere is not seen.
- Destructive-action guard: `wisp hook guard-destructive` (`PreToolUse`, Bash only; code in `cli/src/wisp/guard_destructive.py`) exits 2 with a `wisp-guard:` reason that names the safe way (`trash <path>`, fallback `mv <path> ~/.Trash/`; `/usr/bin/trash` exists on this macOS 27, installed by the system) when a command would irreversibly damage the user's data or Mac. Blocked: `rm` with `-r`/`-R`/`-f`/`--recursive`/`--force` (also under `sudo`, `env`, `bash -c`, after `cd`, and across `;` `&&` `|`) whose target is `/`, `~`, `$HOME`, a top-level user folder (Documents, Desktop, Downloads, Pictures, Movies, Music, Library, Applications, `Library/Mobile Documents`), the brain folder of wisp.json, `~/Wisp`, `/Applications`, `/System`, `/Library`, `/Users`, `/usr`, `/bin`, `/sbin`, `/etc`, a `/Volumes/<disk>` root, or a bare wildcard directly under one of them (`~/Documents/*`, `~/*`, `*` while cwd is one of them); emptying the Trash (`rm` of `~/.Trash`, `osascript` "empty the trash"); `diskutil` erase*/partitionDisk/zeroDisk/secureErase/reformat/apfs delete*, `mkfs*`, `newfs*`, `dd of=/dev/...` (not null/zero/stdout), `> /dev/disk*`, `asr restore`, `tmutil delete*`, `csrutil` (except `status`), `nvram -c`, `launchctl bootout system*`, `shutdown`/`reboot`/`halt`; `chmod -R`/`chown -R` and `find ... -delete`/`-exec rm` on a protected folder; `rsync --delete*` into one; `git clean -f*` and `git reset --hard` only when the cwd (or `git -C`) is inside the brain or `~/Wisp`. Allowed: `rm file`, `rm -rf ./build`, `rm -rf /tmp/x`, `rm -rf ~/Downloads/old-folder` (a named subfolder, or a wildcard with a literal part like `old-*`), `trash`, `mv x ~/.Trash/`, `diskutil list`, `dd if=a of=b`, git in project folders. Any Bcc refuses (`mac_send` does not send with a hidden copy), and the requested cc must equal the window's Cc exactly. `mac_open` refuses a `mailto:` that carries `cc`, `bcc`, `body`, `to`, `from`, `reply-to`, `in-reply-to` or attachment parameters or `&` before the `?` (`mailto:ana@x.com` and `?subject=` open), because it would prepare a message with recipients or text the user never sees. The requested `body`, `to` and `subject` must equal those values byte for byte after `canon` (NFC, CRLF to LF, trimmed), not a substring; a mismatch refuses and the error carries what the window holds so the model can copy it. After the allow, `wisp-mac enviar-janela --regex <send pattern> --esperado <json of body, recipients, cc, subject>` runs in one helper process: it reads the compose window again, refuses on any difference or any Bcc, finds the single AXButton in that window whose label matches the pattern (zero or several refuse), and presses it through `pressElement`, which walks the window once more and checks role, title and description at that index before pressing. There is no separate click process after the last read. The ticket hash is over the tool name, the `app`, to, cc, subject and body, in Python (`wisp_bot.broker.huella`) and in Swift (`BrokerCore.fingerprint(tool:_:)`, `authorize(inputJSON:toolName:)`), pinned by `ticket` and `ticket_mac` in `approval-broker.json`; a ticket for one tool or app is not accepted for another. Clicks always carry `--bloquear <send pattern>`, safe apps included (Calendar invites, iWork "Send a copy", Notes sharing); only outside the safe apps does the helper also run in strict mode (`--estrito`): any click on an AXButton, AXMenuItem, AXMenuButton or AXDefaultButton, or on any element that exposes the AXPress action (`pressable`), asks for the card, whatever its role and label; text fields, search fields, combo boxes, scroll areas and scroll bars, and tabs and a radio button inside an AXTabGroup are free only when no parent in the element's whole chain (not just the 3 ancestors the label check uses) is an AXWebArea (`MacSafety.lineage`): a browser page, an Electron app or any webview can expose role=tab/tablist and run its own handler on press, whatever the app is called. The same chain rule covers the free roles: ARIA role=textbox/searchbox/combobox/scrollbar on a div becomes those AX roles and its click runs the page's handler, so a real HTML input under a web area also asks in strict mode. `pressElement` re-walks the window, recomputes the lineage and the card rule at the index and refuses if the element now asks (a changed DOM). Not verified: an element with `pressable == false` and a non-free role (for example a div with onclick that Chromium does not expose with AXPress) stays exempt, unchanged. A chain that is cut (no root reached in the tree, over 64 parents, or a point hit whose parent walk did not end at the AXApplication) is treated as unknown and asks, and there is no toolbar, link or group exemption (a toolbar Run or Build button, or a web page posing as role=toolbar, asks). For a point click the same rule applies to the element and up to 3 ancestors (an image inside a button asks); text fields, links, tabs, disclosure triangles, scroll bars, static text and the like do not, and neither does a button with a label inside an AXToolbar (toolbar navigation; an unlabelled toolbar button does ask). Every menu action outside the safe apps asks (`acao=menu`: the real item is first resolved with `menu --exato --resolver`, its title must equal the typed last component, then the card, then the press); inside the safe apps `menu` always passes `--bloquear`, and the helper resolves the item first (a partial label such as `Message > Sen` resolves to `Send`), applies the pattern to the item's real title, and re-resolves and compares the title right before pressing. A point click is judged by the app that owns the element under the point (its AX pid); the helper checks the element and up to 3 ancestors (title, description, help, identifier); `pressElement` walks the window again right before pressing and refuses unless role, title and description still match and the pattern still does not match.
- Scripts (`mac_script`, or `mac_send acao=script`): no pattern decides that a script is safe, every script asks. Before the card, and without one if it hits: the script text and every `do shell script "..."` / `doShellScript('...')` body go through the secrets guard (`hook_guard_secrets`, `scan_text`, and a keychain/ssh pattern: `security find|dump|export|add|delete|import-*`, `find-generic-password`, `Library/Keychains`, `.keychain`, `~/.ssh`) and a hit is refused outright; they also go through `guard-destructive` and `guard-outbound` (mail sends; the UI-script rule is skipped here because the card is the control). - `guard-outbound` (best effort, a barrier and not a lock). The helper is recognised by `Path(word).name == "wisp-mac"` or any path containing `Contents/Helpers` in command position of the shell-aware parser the email guard already uses (`_segments`, `_command_index`: wrappers such as `env`, `sudo`, `exec`, `command`, `timeout`; `bash -c` bodies up to depth 3; heredoc bodies; per-line fallback when quoting does not parse). The deny patterns are glob matches on the command text; a free Bash shell can still write that plist or the callers folder through an interpreter, an encoded string or a variable, which is inside the accepted free-Bash limit below. ## Self-learning

- Store: `<brain>/wisp/aprendizados.md`, a short heading and one line per lesson, `- <rule> · <YYYY-MM-DD> · <origin>`; only lines starting with `- ` count. Lessons are deduped by their rule folded to lowercase, no accents or punctuation (the first stays); past 40 the oldest are dropped (`wisp aprender add` prints a stderr line naming each). A rule with a token-like secret is refused; the rule is cut at 240 characters and the ` · ` separator inside it becomes ` - `.
- Capture: `wisp aprender add "<rule>" [--origem <text>]` (`já sabia` for a duplicate); the agent is told to call it by the hook text itself, with the absolute path of the running `wisp`, so no per-surface prompt changes. The `ask` permission rules (`Bash(*aprender add*)`, `confirmar`, `descartar`) in `harness/settings.json` and in the app's and bot's `--settings` make the engine prompt the user before any of the three runs; per the Claude Code docs an `ask` rule prompts even in bypassPermissions mode and wins over a user's own `allow`. `wisp setup` also removes the legacy `Bash(~/.local/bin/wisp aprender add:*)` auto-allow older installs carry (`REVOKED_ALLOW`). `wisp hook guard-lessons` (`PreToolUse`, same three settings, never in the harvest's) denies (exit 2) Write/Edit/MultiEdit/NotebookEdit on the active and pending lessons files and Bash commands that name `aprendizados` next to a write operator (`>`, `tee`, `sed -i`, `mv`, `cp`, `python -c`...); best-effort, a shell can always find another way. The brain harvest prompt has a step for the same lines (corrections and preferences only, facts stay in notes), but it writes them to `<brain>/wisp/aprendizados-pendentes.md`; right after the model child exits OK, `quarantine` puts the active file back exactly as it was before the harvest (the model can only add, an edited or removed active line is restored) and moves anything it left there into the pending file. The harvest runs under the scope guard and `wisp/` is inside the brain.
- Confirm: harvested rules wait in the pending file and the agent never sees them until the user runs `wisp aprender confirmar <n>` (or the app's Brain settings); `descartar <n>` drops one. Python and Swift both write the active file first and only then remove the pending line (a failed write loses nothing) and skip a rule already active (same folding as the dedupe).
- Use: `wisp hook aprendizados` (`SessionStart`, in the app's and bot's `--settings` and in `harness/settings.json`) prints the active rules (without date/origin) framed as preferences the user taught the agent, plus the `aprender add` instruction. No brain configured or any error: prints nothing, exit 0. Lessons saved during a conversation reach the agent from the next session start (a new conversation, or a resume), not the one that is running. The once-per-session marker (`aprendizados-sessoes/<session_id>`) stores a hash of the active rules, so a resumed session gets the text again only when the active set changed (for example after a confirm), never for pending ones. A session started under both `harness/settings.json` and `--settings` may receive the text twice.
- Undo: `wisp aprender listar` / `wisp aprender remover <n>`; the app's "O que o Wisp aprendeu" removes by line text (not by number), so a concurrent write never removes the wrong rule.

- Frontmatter: `BrainDocument` keeps the exact opening and closing fence lines and every line it does not touch, so open-edit-save without changes is byte-identical. Autosave runs per tab, so editing note A and then note B within the delay never cancels A's save. A write stages the bytes in a system replacement folder on the note's volume (outside the brain); if that folder cannot be made or the rename fails with EXDEV (SMB, FUSE, external disks) it tries `<brain>/.git/wisp-tmp` (git never tracks `.git`), and only when there is no `.git` on the same volume a hidden `.wisp-tmp-*` file next to the note. - Note engine lockdown (`wisp reuniao nota`): Claude runs with exactly this argv (pinned by a test): `--print --no-session-persistence --tools "" --setting-sources "" --strict-mcp-config --mcp-config '{"mcpServers":{}}' --disallowedTools <every built-in> --permission-mode default --settings <hooks off, no allow rules> --disable-slash-commands --append-system-prompt <prompt>`, in a fresh temp folder deleted afterwards (never the meeting folder). The transcript sits between `BEGIN TRANSCRIPT <nonce>` and `END TRANSCRIPT <nonce>` lines (random nonce per run, removed from the text if it appears there), and the system prompt names the markers as data.
- System-audio permission: silence never becomes a stored "denied". While the current recording has been silent for 10 s, `SystemAudioWatch` makes the tab show a neutral grey hint ("Não estou ouvindo o Mac...") with the Settings button, not the yellow permission card; it clears when sound arrives and only "granted" is remembered.
- `MeetingPipeline.process` does nothing for a `noted` meeting whose `nota.md` exists; only `regenerateNote` rewrites it.
- The final pass has a pause gate checked before every recognizer call; the app holds it while a recording runs and it resumes by itself. The gate and the queue wait loop propagate cancellation (quitting the app cancels them). Live and final passes use two separate recognizers (two `AsrManager`s), never one shared. Stopping awaits the live worker (`stopAndWait`) before the final pass; a late result is dropped, and `transcript.live.json` is only read when there is no `transcript.json`.
- Live queue: finals are never dropped; a "…" typing mark is skipped while a job of that channel waits; with 3 or more finals waiting the tab shows "Transcrição atrasada". Recognizer calls in 60 s of one channel, measured on synthetic audio with the old and new streamer (before: 5 s window every 4 s plus a partial every 2.75 s; after: one call per segment): silence 0 before and 0 after; one speaker talking non-stop 30 before (15 finals + 15 partials, 119 s of audio decoded) and 4 after (60 s decoded; about 3 per minute once running, the 20 s cap); 50% speech in 4 s bursts with 4 s pauses 23 before (8 partials + 15 finals, 98 s decoded) and 8 after (37 s decoded); 2 s bursts with 2 s pauses 30 before and 15 after.
- Live times: `LiveAudioAligner` places each channel on one shared origin (the first chunk's host time), pads gaps over 25 ms with at most 2 s of silence (a longer gap is reported to the streamer, which flushes what it heard and skips ahead on the timeline without buffering zeros), drops overlap and trims audio before the origin, so both live channels share a clock. The file's own origin is the earliest first chunk of both sources, so a live time can differ from the file's by the start skew between the two sources.
- Model: every file's SHA-256 is computed after the download and stored in `.wisp-verified` (JSON); the app re-checks every file against the compiled manifest (`verify`: SHA-256 for the LFS files, git blob SHA-1 for the others; the marker only says an install finished, it never supplies expected values) before marking the model ready. Manifest paths with `..`, `.`, empty parts, a leading `/` or a backslash are refused before any download.
- Brain export: `[[`, `]]`, `|`, CR and LF are removed from the title in the index line; a `meetings` folder or index that resolves outside the brain (symlink) is refused and nothing is written.
- Attribution: the CC-BY-4.0 notice (NVIDIA author, FluidInference conversion) is shown on the model download card and in Ajustes > Sobre.
- Cancellation: `WispNoteWriter` runs `wisp reuniao nota` through `CommandRunner` with a `CommandCancellation`; cancelling the Swift task (a cancelled queue, "Cancelar nota", app quit) sends SIGTERM to the command's whole process group (then SIGKILL after the runner's grace), which includes the engine child. A cancel before the process starts kills it as soon as it registers. "Gerar nota de novo" is a task the tab can cancel.

## core / Calendar (the Agenda tab's engine)

- Separate from the agent's `AgendaService`: the UI talks to `CalendarBackend` (`EventKitCalendarBackend` in production, a fake in tests); the agent path (`wisp agenda`, `wisp-agenda`, the approval hooks) is untouched. An edit made by the user in the tab is the user acting, so it does not go through an approval card; the agent keeps its card. Reminders are the exception on purpose: the side list reads and checks off through `AgendaService` ("lembretes --pendentes", "concluir-lembrete"), the same commands the agent uses.
- Why EventKit in the app and not the helper: the app already has the Calendars entitlement and both usage strings; a helper call costs a process launch plus JSON per read, cannot deliver `EKEventStoreChanged` (live refresh), and cannot keep an `EKEvent` for a recurring-scope save. All EventKit work runs on one serial queue and returns value types, so the main thread never waits on EventKit. Caveat: TCC grants are per process identity, so the app's own status is what the tab trusts; if the helper was granted from Ajustes > Agenda the app may still show "Permitir acesso" once (one system prompt, attributed to Wisp). Not verified on a real prompt.
- Occurrence identity: a recurring event keeps one `eventIdentifier`; the occurrence is `EventRef(id, start)` (the agent's `id@<start>` convention) and the lookup is the same one `EventKitStore` uses (a ±1 day window matched on id and start within 1 s). `CalEvent.uid` is `id` for a single event and `id@<epoch>` for an occurrence.
- Recurrence rules are modelled in full (frequency, interval, end by count or by date, days of the week with their week number, days of the month, months, weeks and days of the year, set positions), so reading and writing a rule loses nothing. The detail form sends a recurrence change only when the user touched the "Repetir" section (`RecurrenceForm`); a title-only edit sends none, an interval edit keeps the end date and the weekdays, changing the frequency drops the day detail. A recurrence change is never sent with "só este" (the editor and the EventKit backend both drop it).
- Recurrence scope: "só este" saves with `.thisEvent`; "este e os próximos" saves the occurrence with `.futureEvents`; "todos" saves the series' first occurrence (`event(withIdentifier:)`, no start) with `.futureEvents`. For "todos" with a time change the editor shifts the first occurrence by the same delta the dragged occurrence moved, never to the dragged occurrence's absolute time. A non-recurring event never asks. Undo of a detached occurrence is best effort (EventKit may give it a new identity); undo of a delete recreates the event from a snapshot (guests and the organizer are not restored).
- Undo (`CalendarEditor`, 30 entries): create undoes by deleting; an edit restores only the fields that edit changed, with the same scope it was saved with (the exact original rule when the recurrence was changed); delete recreates from a snapshot: "este e os próximos" and "todos" recreate the series with its rule as a new series, "só este" recreates the occurrence as a standalone event because EventKit has no public way to put an occurrence back into a series. The result message says what was not restored (guests, cancellations already sent, the series identity). Deleting "todos" snapshots the series' first occurrence (not the clicked one), so undo brings back every repetition with the original count; "este e os próximos" on a series that ends by count recreates it counting from the clicked occurrence, and the message says so. Undoing a "este e os próximos" edit restores the fields but does not merge the split series back, and the message says that. An event with more than one recurrence rule shows the rule section read-only ("Regra personalizada mantida") and a save never touches its rules (`CalEvent.recurrenceRuleCount`; the editor and the backend both drop a recurrence change). The interval and count steppers always include the current value. Undo of a delete also says, in the result message, when the series master could not be read for "todos" (the series is recreated from the clicked occurrence), when the series had more than one recurrence rule (only the first is recreated) and, for "todos", that series exceptions (edited or deleted single occurrences) are not restored. An entry whose event no longer exists is dropped and the user is told; any other failure keeps the entry. When a recreate gives an event a new identifier, older entries that pointed at the old one are updated. Read-only calendars refuse edit and delete before reaching EventKit; an end before the start is refused. Before an edit or delete is saved the backend refreshes the `EKEvent` and compares `lastModifiedDate` with the one the UI read; a difference is refused ("mudou fora do Wisp"), the agenda reloads and nothing is saved. Delete always asks first; when there are guests the question says a cancellation will be sent and cannot be undone.
- Guests are shown with their status and are read-only: EventKit has no public API to add or remove an attendee. Alerts are relative offsets (absolute alarms are left alone); recurrence supports daily, weekly, monthly and yearly with an interval and "after N occurrences"; a rule the editor cannot represent is kept as is unless the user changes "Repetir".
- All-day events: EventKit stores them from 00:00 to 23:59:59 of the last day; the UI writes the next local midnight minus one second (`CalendarDates.allDayEnd`, so a 23 h or 25 h day on a daylight-saving change still ends at 23:59:59) and reads the last day as `end - 1 s`. An end exactly at the next midnight, which other clients write, also reads as the previous day. Not verified against how Calendar.app draws an end at the next midnight, which is why the Apple convention is kept.
- Wall-clock math: grid positions, moves, resizes, working hours and quick-create times are built from the local hour and minute (`date(bySettingHour:minute:second:of:)` through `GridMath.date`), never from elapsed seconds since midnight, so a daylight-saving day keeps 15:00 at 15:00; a time that does not exist (02:30 on the spring-forward day) lands after the gap.
- Layout (`EventLayout`): events are sorted by start (longer first), grouped in clusters that share time, given the first free column, and then widened over free columns to the right. A multi-day timed event contributes one segment per day, clamped to that day. A segment shorter than 20 minutes is drawn 20 minutes tall. `EventIndex` keys events by day number (days since 2001-01-01 in the user's calendar) and puts a multi-day event on every day it touches.
- Grid math (`GridMath`): snap is 15 minutes, absolute (an off-grid start lands on the grid when moved); minimum length 15 minutes; a move is clamped inside the day for events shorter than a day; a click without a drag creates one hour; a drag creates from the snapped-down start to the snapped end.
- Quick create (`QuickEventParser`, pt-BR and en together): extracts, in this order, `#calendar` or "no calendário X / on calendar X" (matched against the writable calendar names, longest first, accent and case insensitive; an unknown name is returned as typed and the UI refuses it), `@ local` or `local: x` (not an email, not `@ 3pm`), "dia todo / all day", relative "em 2 horas / in 30 minutes / daqui a 45 min / em 3 dias", a duration after "por / for / durante" (1h, 1h30, 1h e 30min, 90 minutes, 1.5h, meia hora, half an hour), ISO and `dd/MM[/yyyy]` dates (`MM/dd` only when the second number is above 12), a time range ("10-11", "14h-15h30", "das 10 às 11", "3pm-4pm", "from 9 to 10"), a single time ("13h", "13h30", "14:30", "1pm", "às 9", "at 3", "meio-dia", "noon"), then dates (hoje, amanhã, depois de amanhã, weekdays with "próxima/next", "N de mês", "mês N", "dia N", "the 3rd") and day parts after a date ("de manhã" 09:00, "à tarde" 15:00, "à noite" and "tonight" 20:00). What is left, minus trailing connectors, is the title. Rules worth knowing: only a date means all-day; only a time means the next time that hour happens (tomorrow when it already passed); an explicit date in the past stays in the past; "próxima/next + weekday" is the next occurrence strictly after today; a bare hour after "às/at" from 1 to 6 reads as pm; a bare range ("10-11") needs a start of 6 or later and is refused after "dia/day/the/on"; a range whose end is not after its start tries +12 h and then +1 day; with no date and no time the event starts at the next quarter hour. No weekday abbreviations in pt-BR ("sex", "seg" collide with words) and no month abbreviation without a number next to it. Quantities take at most 4 digits and a duration must be 1 minute to 7 days, otherwise the words stay in the title (so a 20-digit number cannot overflow). Matching runs on a folded copy built one character at a time with the same UTF-16 length as the original (a character whose fold changes length, like "ﬁ" or "ß", is masked), so ranges never drift. Text that parses to nothing stays a plain title.
- Meeting links (`MeetingLinks`): Google Meet (`meet.google.com/<code>`), Zoom (`zoom.us`/`*.zoom.us|.zoom.com` with `/j /my /s /w /wc /join`, `zoommtg:`), Teams (`teams.microsoft.com/l/meetup-join`, `teams.live.com/meet`, `msteams:`), Webex (`*.webex.com/<path>`), Slack huddle (`*.slack.com/huddle`), FaceTime (`facetime.apple.com/join`). Order: the event URL (also a meeting URL wrapped inside another URL), then the location, then the notes; the first match wins. Anything else on those hosts is not a meeting. "Next meeting" is the earliest event with a link that has not ended (a running one counts), skipping all-day, declined and linkless events. Alerts are planned for the next 48 h, only events with a link, at start minus the lead (default 1 min); one already inside the lead fires in 1 s.
- Time zones: the secondary columns show the same instant in other zones with a `+1/-1` day marker; the event zone picker keeps the instant (the wall clock changes) and the DatePickers render in the event's zone. `reinterpret` (same wall clock, other zone) exists for callers that want the other behaviour.
- Availability: working hours (default Mon-Fri 09-18, in the Mac's zone) minus the busy time of the events on the visible calendars (all-day, declined and "free" events do not block), never before now, slots under 30 minutes dropped, optional buffer. Text is built by hand, not by `DateFormatter`, so it does not change with the system locale: `seg, 23/11: 09:00–11:30 e 14:00–16:00` (pt-BR, 24 h) or `Mon, Nov 23: 9:00 AM–11:30 AM and 2:00 PM–4:00 PM` (en), under a header with the zone id and offset. A public booking link is out of scope.
- Meeting to event link: "Gravar e transcrever" calls the current `MeetingRecorder` through `MeetingRecordingModel.start(linkedTo:)`; once the folder exists it writes `event.json` inside it (event key, title, start, calendar) and an entry in `~/.local/state/wisp/agenda-links.json` (0600). The recorder, `RecordingMeta` and the audio path are not changed; a later transcript step reads `event.json` for the title. The recording has no transcript note yet in main, so the event shows "Gravação: <pasta>" and the note link only exists after "Criar nota da reunião". A corrupt or missing link file reads as empty.
- Brain note: `meetings/YYYY-MM-DD-HHhMMm-<slug>.md` under the profile's memory root (the naming of the brain's own meetings folder), with frontmatter (date, tags, context, attendees, status, created, aliases) and TL;DR, Context, Attendees and Notes sections; it never overwrites an existing note. The note's name is appended to the event notes as `[[name]]` when the calendar is writable. A `[[name]]` (alias and heading stripped) in the notes or the link entry shows an "open note" button that opens it with the same Obsidian URL the Memory tab uses.
- Preferences (`WispSettings.agenda`): hide titles in notifications and the menu bar (off by default; shows "Reunião"; Ajustes > Agenda), view mode (default week), hidden calendars and hidden accounts, secondary zones, working hours, availability language, alert lead (0-120 min), alerts on/off, menu bar on/off, Google hint dismissed, sidebar open. Hiding is applied when reading, so a toggle is instant and nothing is refetched. "Restaurar padrões" keeps them.

Cmd+J is local to the tab, there is no global hotkey.
- Notifications use `UNUserNotificationCenter` (asks for permission the first time an alert is scheduled); the pending requests are replaced when the plan changes and fire even if the app is closed. The menu bar item (`NSStatusItem`) shows the next event within 12 h with a countdown; its menu offers "Entrar" and "Abrir na Agenda".
- Access card: shown when the app's own Calendar status is not granted: "Permitir acesso" when undetermined, "Abrir Ajustes do Sistema" otherwise. A hint card appears when no calendar's account name mentions Google or Gmail (a Workspace account with a custom address can trigger it; "Dispensar" hides it for good) and opens Internet Accounts.

## Meetings: brain sync

- Calendar link: `MeetingEventMatcher.pick` takes the events of the day around the start and keeps the one with the largest overlap with the window `[start, start + 5 min]` (the end is not known while recording). All-day, declined and zero-length events are ignored; a tie goes to the event with attendees, then the shorter one, then the id. An event started from the Agenda ("Gravar e transcrever") is used as is. With no event picked, `CalendarModel.meetingContext(at:)` runs once after the recording started, only when `eventsAccess()` is already `.granted` (it never asks for permission), and only the visible calendars count. A late answer after the recording stopped is dropped.
- The event is kept in `meta.json` as `event` (title, calendar, organizer, attendees without the user, notes, call link). It is written when the recording stops, in the same update as bookmarks and checklist, because the recorder rewrites `meta.json` from its own copy at stop. The row title becomes the event title until the summary gives a title.
- Where it goes: `<brain>/meetings/YYYY-MM-DD-HHhMMm-slug.md` (the same folder and pattern as the old "Salvar no brain" copy; the brain is the one in Ajustes > Pastas, passed as `--brain`). The slug is the event title, else the summary title, else "reuniao", lower case, ASCII, hyphens, 48 characters at most. The folder is created only inside an existing brain; a `meetings` folder that resolves outside the brain, or a missing brain, writes nothing and the failure shows on the meeting as `brain_error`. Time is the recording start in the local zone.
- Writing is atomic and never overwrites: the text goes to a temp file in the folder and is hard-linked to the final name, trying `name.md`, `name-2.md`, `name-3.md`. When `meetings/meetings-index.md` exists, one line `- [[name]] — title (YYYY-MM-DD)` is appended (temp file and rename, the file mode kept, never twice for the same name, 200 characters at most); the index is never created. Nothing else in the brain is touched: no stub notes, no edit of the notes that are linked to.
- Note shape: frontmatter (`tipo: reuniao`, `sync: wisp-reuniao`, `data`, `duracao`, `calendario`, `participantes` as `"Name <email>"`, `organizador`, `link`, `gravacao`, `resumo_gerado`), `# title`, `**Participantes:**` (omitted without a calendar event), the event description as a quote (2000 characters at most), the summary sections `## Resumo`, `## Pontos principais` and `## Ações` taken from `nota.md` only when `note_state` is `generated` (metrics, bookmarks, checklist and the transcript stay out of the brain), and `## Transcrição` with a `file://` link to `nota.md` (or `transcript.json` when there is no note yet).
- Wikilinks come from the brain index read-only (`BrainIndex.sync` writes only its own database in the state folder). A name is linkable when exactly one note claims it as title, file name or alias (accents and case ignored); two notes claiming the same name make it ambiguous and it stays plain text, and notes under `meetings/` are never targets. Attendees are tried by name then by email, and an alias or case difference is written as `[[target|shown text]]`. In the summary only a name that starts with a capital letter is linked, names of fewer than 3 characters or made only of stop words are skipped, text in headings, inline code, existing links and URLs is left alone, and each note is linked once per document. Index unreadable means no links, never a failure.
- Updating: the note path is saved as `brain_note`. Before creating, the sync looks for the meeting's note: first the `brain_note` path, then every `.md` under `meetings/` (recursive) and every indexed note named like `YYYY-MM-DD-HHhMMm-…` elsewhere in the brain, keeping the one whose frontmatter has the `sync: wisp-reuniao` line and a `gravacao:` equal to this recording folder. A renamed or moved note is therefore updated in place and its new path is returned (and saved as `brain_note`), never duplicated. When `brain_note` points to a file that no longer exists and no marked note is found, the sync fails with "a nota da reunião foi movida ou apagada no brain" and creates nothing; `wisp reuniao brain --recriar` (used by the "Salvar no brain" button, which is an explicit click) creates it again. A `brain_note` that exists without the marker (an old manual copy) is never rewritten and a new note is made. The update replaces only the line `> Resumo ainda não gerado.` with the linked summary and flips `resumo_gerado`; if the user edited that line away, or the summary is still missing, the file is left untouched.
- Setting `autoSummary` (default on; old settings files read as on), in Ajustes > Geral > Reuniões and the Reuniões tab settings page. Its value at the moment the recording stops is saved in `meta.json` as `summary_deferred`. On: transcription, then `wisp reuniao nota`, then `wisp reuniao brain`. Off: transcription, then `wisp reuniao brain` with no summary (placeholder line), the status stays `transcribed` and the library no longer queues it for a note; the meeting shows "Gerar resumo", which runs the note and then updates the same brain note. "Gerar nota de novo" on a meeting whose placeholder is already filled does not change the brain note.
- Button: when `brain_note` points to a file that exists the meeting button reads "Abrir no brain" and opens it; otherwise (old meeting, failed sync, deleted note) it reads "Salvar no brain" and runs the same `wisp reuniao brain` sync, no longer the old file copy. `MeetingBrainExport` stays in core but the app does not call it.
- Concurrency: creating, the index append and the summary fill run under an exclusive `flock` on `meetings/.wisp-index.lock`. Both rewrites (`rewrite`) read the file, build the new text in a temp file, re-read the file and compare SHA-256 before the rename; if it changed (an editor saved meanwhile) they redo it once from the new content and fail with a retry message if it changed again. If the hard link used to create a note is refused (exFAT, SMB), the note is created with `O_CREAT|O_EXCL`; the temp file is always removed.
- Text and privacy: every one-line value from the calendar (title, names, emails, calendar, organizer, link) is collapsed with `" ".join(x.split())`, so a newline in an invitation cannot add headings or frontmatter lines. `gravacao:` and the transcript link are written relative to the home folder (`~/Wisp/reunioes/<folder>`, spaces percent-encoded in the link) when the folder is under it, so the macOS user name does not reach the vault; the app has no `wisp://` scheme, so the link is that `~` path.
- Failures: a brain write that fails never fails the meeting; the reason is saved as `brain_error`, shown in the meeting and cleared by the next successful sync. `wisp reuniao brain` takes its own lock (`.brain.lock` in the recording folder).
- Not verified at runtime: nothing here ran with the app, real Calendar access or a real model. Tests use fake events, a fake brain index, temp folders and a fake note writer.

## Meetings: copilot

- Where things live: pure logic in `core/Sources/WispCore/Meetings` (`MeetingMetrics`, `MeetingNudges`, `MeetingEntities`, `MeetingBrainLookup`, `MeetingBookmarks`, `MeetingCopilot`, `MeetingRecordingLimit`, `MeetingWebhook`), engine calls in `cli/src/wisp/reuniao.py` (note) and `reuniao_copilot.py` (`wisp reuniao assist` and `wisp reuniao prep`, JSON on stdin, one JSON line out), the app side in `app/Sources/Meetings` (`MeetingCopilotModel`, `MeetingCopilotViews`, `MeetingEngineClient`, `MeetingWebhookSender`).
- Engine lockdown is shared: `assist`, `prep` and the three note extractions all go through `engine_argv(cfg, system)`, so the argv is the one pinned for the note with only `--append-system-prompt` changing; the local path calls Ollama's chat API with `tools: []`. Codex is never run: with Codex active they use Claude if `claude --version` runs, else the local model, else fail with the same reason as the note. Everything the model reads (transcript, event notes, attendees, brain snippets, already-shown items) sits between `BEGIN <label> <nonce>` and `END <label> <nonce>` lines with a random nonce removed from the text, and the system prompt names those markers as untrusted data.
- Assist: off at the start of every recording. `AssistGate` allows a call only when no call is running, at least 40 s passed since the last one started, and there are finals that the last call did not see. The window is the finals of the last 240 s (at most 6000 characters, the end kept). The reply is parsed line by line (`pergunte:`, `responda:`, `lembre:`), at most 3 items of at most 200 characters; the panel keeps the newest 6 and drops repeats ignoring case and accents. Turning the toggle off, stopping the recording or quitting cancels the call (SIGTERM to the process group).
- Brain lookup: cheap and local, no engine. `EntityDetector` takes capitalised words that are not at the start of a sentence (or runs of two or more), the 1 to 2 capitalised words after a keyword (cliente, projeto, empresa, contrato, proposta, fornecedor, produto, sistema, ferramenta, squad and English equivalents), and codes (4 or more digits, or letters with digits). `LookupGate` sends at most 2 new queries per round, at least 20 s apart, never the same one twice (case and accents ignored), 40 per meeting. The search is `wisp brain search <q> --root <brain> --limit 3`. That command exists only in the Brain tab PR #23 (not merged; `feat/brain-rag` has `wisp mcp brain` but no `brain search`), so `wisp brain search --help` fails today and the panel stays hidden. When the command exists the panel shows a toggle, off at the start of every recording; a second toggle, also off, lets "Outros" lines trigger searches (by default only "Você" does); hits show only note titles until one is expanded (then the snippet), and the card warns that titles are visible when sharing the screen. Turning the toggle off clears the hits. Its output format is not in this branch, so `BrainSearchCLI.parse` accepts a JSON array or an object with `results`, `hits`, `notas` or `notes`, with `path` (or `arquivo`, `file`), `title` (or `titulo`) and `snippet` (or `trecho`, `excerpt`); anything else shows no hit. Opening a note is refused when the resolved path leaves the brain folder.
- Metrics (`MeetingMetricsCalculator`): speaking time of a channel is the union of its final lines (overlaps counted once); talk share is Você over Você plus Outros speaking time; words per minute is words over speaking time, 0 under 10 s of speech; a question is a run of `?` in a line (so "?!" counts once), which means the recognizer must punctuate; the longest monologue joins lines of one channel at most 4 s apart and ignores interjections of 2 words or fewer from the other channel; silence is the time inside the meeting with no final line on either channel. Live metrics refresh every 2 s. The final numbers are recomputed from `transcript.json` right before the note is written and saved as `metrics` in `meta.json` (keys `duration_s`, `you`, `others`, `silence_s`; per channel `words`, `speaking_s`, `wpm`, `questions`, `longest_monologue_s`).
- Nudges: off at the start of every recording. At most one chip at a time, never within 300 s of the previous nudge, and the same kind waits 600 s. In priority order: the user has been talking for 3 min straight ("Monólogo de N min", only for Você); Você has at least 75% of the speaking time once 5 min were spoken; no question on either side for 10 min. A chip goes away after 30 s or on its x. No sound, no notification, nothing blocks.
- Bookmarks: the button and the global shortcut Ctrl+Option+B (registered only while recording, so it is free the rest of the time; if another app owns it the shortcut silently does not register and the button still works) store the seconds since the recording started. In the transcript a bookmark row sits after the last line that started at or before that time. They are saved in `meta.json` as `bookmarks` when the recording stops, so a crash loses them. In the note, `## Marcadores` lists each one with the 3 lines before and the 2 after.
- Prep: the card in the idle Reuniões screen lists today's events (`wisp agenda eventos --hoje`, all-day events left out) or takes a typed description; `wisp reuniao prep` returns up to 8 checklist items and 8 probing questions (questions become items starting with "Perguntar:"). Items are checkable during the recording; the state is saved in `meta.json` as `checklist` and printed as `- [x]` / `- [ ]` in the note. Event title, notes and attendees are sent to the engine, which the card says. A linked event and the checklist feed the assist context.
- Note: `write_note` runs three extractions in parallel threads, each with its own prompt (`visao` with the title and Resumo, `pontos` with key points by topic and Você/Outros lines, `acoes` with the action items in the same `- [ ] <action> — responsável: <owner> — prazo: <date>` shape as before) and its own 2 attempts. All three failing leaves the raw note with the reason; one failing keeps the others and writes "Seção não gerada: <reason>" under its heading. The old "Decisões" section is folded into the overview prompt ("including any decision"). After the engine sections come `## Métricas`, `## Marcadores`, `## Checklist` (each only when there is data, rendered by Python from `meta.json`, never by the model) and `## Transcrição`. The note engine's wall time is now bounded by the slowest extraction, not the sum, but a local model may serialise them.
- Webhook ports: any port is accepted (`https://host:8443/…`, a custom port, and so on). The protection is that every resolved address must be public and the connection goes to that address, not a port allow-list; the card and `Host` header show the port when it is not 443. Ajustes says so.
- Webhook: configured in Ajustes > Geral > Reuniões (off). The URL and the optional signing secret are in the Keychain (service `<bundle id>.webhook`, accounts `url` and `secret`), never in `settings.json`; the secret is 32 random bytes in hex, created when signing is switched on and copyable from Ajustes. After the pipeline finishes a meeting with a generated note (not a raw one, not a regeneration, not one already sent) and the toggle is on, the library builds the payload and shows a card with host, masked path (`https://host/•••`), a preview (first 280 characters of the overview and the counts) and the size; nothing leaves the Mac before Permitir, and the pending payload is held in memory only. The payload is a whitelist built from three sections of `nota.md` (`## Resumo`, `## Pontos principais`, `## Ações`, first occurrence only, lines starting with `>` dropped): `event`, `title`, `started_at`, `duration_s`, `overview`, `key_points`, `action_items` (`text`, `owner`, `due`) and `metrics` (numbers). Bookmarks, the checklist, the transcript and the metrics text are never read. URL rules (`MeetingWebhook.validate`; there is no `web_fetch` in this repo): https only, no user or password, at most 2048 characters, no `localhost`, `.local`, `.internal`, `.lan`, `.home`, `.corp`, `.test`, `.invalid`, `.example`, no single-label host, no IP literal in loopback, private, link-local, CGNAT, multicast, reserved or documentation ranges (also the decimal, hex and short forms `inet_aton` accepts); IPv6 only inside 2000::/3, IPv4-mapped and 6to4 (2002::/16) judged by the embedded IPv4, Teredo (2001::/32) and 2001:db8::/32 refused. At send time the host is resolved once, every address must pass the same rules, and the request goes over `NWConnection` to the numeric address (no second lookup), with TLS SNI and the certificate trust evaluated for the host name, `http/1.1` only, TLS 1.2 or later, no proxy, a hand-written `POST` with `Connection: close`, a 20 s limit, and a 3xx answer treated as a failure. With signing on, the request carries `X-Wisp-Timestamp: <unix seconds>` (taken when Permitir is processed, not when the card was shown) and `X-Wisp-Signature: sha256=<hex>`, the HMAC-SHA256 of `<timestamp>.<body>`; a receiver should refuse timestamps older than about 5 minutes and can cache signatures it has seen. The secret is read from the Keychain at send time and is never held in the pending payload. The host is built once by `MeetingWebhook.validate` (`WebhookTarget.host`, lowercase, no brackets) and is the only value used to resolve, for SNI and for the `Host` header; `validate` refuses a URL containing a backslash, a non-ASCII or control character, a percent-encoded host, a trailing dot, or where `URL` and `URLComponents` disagree about the host. If a connection fails before the request was handed to the network the next address is tried; once the request was handed over (even if the answer never came) the send stops and reports that it may have arrived, so it cannot be delivered twice. The card has an expander with the exact bytes of the body (the same `Data` that is signed and sent, decoded as UTF-8, no re-encoding), and a nested "formatado" expander with a pretty-printed copy; it says the overview and key points are model output and may quote speech. A success stores `webhook_sent_at` in `meta.json`; "Agora não" is not stored. Not verified at runtime: the TLS verification and the NWConnection exchange have no unit test (the request bytes, signature, status parsing and address rules do).
- Recording limit: `RecordingLimitClock` measures the real time since the start (a monotonic clock that keeps counting while the Mac sleeps) minus explicit pauses only (`pause` and `resume`; the recorder has no pause yet, so nothing calls them). Sleep and stalls count: waking after the limit stops the recording at once. The warning comes once when 5 min remain (not for limits of 5 min or less, and not when the first tick is already past the limit), the stop once at the limit, with the message "A gravação parou: chegou ao limite de 2 h de gravação." Choices in Ajustes: 30, 60, 90, 120 (default), 180, 240 min; the stored value is clamped to 15 to 720 min.
- Not verified at runtime: nothing in this section was exercised with the app running (no recording, no engine call, no webhook request, no global shortcut press). The unit tests cover the logic and the Python engine calls use fakes.
## Drawings research (Excalidraw and JSON Canvas)

Sources: the user's Excalidraw plugin 2.25.3 (`.obsidian/plugins/obsidian-excalidraw-plugin/main.js`, `manifest.json`, `data.json`, read only), the npm registry, the `@excalidraw/excalidraw` 0.18.1 package, and https://jsoncanvas.org/spec/1.0/.

- Real format. A plugin drawing is `---` frontmatter (`excalidraw-plugin: parsed`, `tags: [excalidraw]`, plus whatever the user added), the "Switch to EXCALIDRAW VIEW" banner, then `# Excalidraw Data`, `## Text Elements`, optional `## Element Links`, optional `## Embedded Files`, `%%`, `## Drawing`, a fenced block, `%%`. Anything after the closing `%%` is the user's (e.g. a `## Mudanças` log) and the plugin leaves it alone. The plugin constant `FRONTMATTER` is the exact header of a new drawing.
- Compression. `compress()` in `main.js` is `LZString.compressToBase64(json)` cut into 256-character chunks joined by a blank line (`\n\n`), trimmed; `decompress()` strips `\n`/`\r` and runs `decompressFromBase64`. Checked on the 6 real files: 4 are ```` ```compressed-json ````, 2 (written by an agent tool, not by the plugin) are ```` ```json ````; every compressed block decompresses to valid scene JSON (`type: excalidraw`, `version: 2`, `source`, `elements`, `appState` with 34 keys, `files: {}`), is tab-indented (`JSON.stringify(scene, null, "\t")`), and `compressToBase64(decompressed)` equals the stored text, so a faithful LZ-String port reproduces the plugin's bytes.
- What the plugin accepts on read. `DRAWING_REG` / `DRAWING_COMPRESSED_REG` match both ```` ```json ```` and ```` ```compressed-json ````. When the file's form differs from the `compress` setting the plugin only marks the drawing dirty and rewrites it in the setting's form the next time it saves; it does not refuse. Plain `.excalidraw` files are also recognized (`extension === "excalidraw"`). The user's settings: `compress: true`, `folder: "Excalidraw"`, `drawingFilenamePrefix: "Drawing "`, `drawingFilenameDateTime: "YYYY-MM-DD HH.mm.ss"`, `useExcalidrawExtension: true`, `compatibilityMode: false`, `templateFilePath: "Excalidraw/Template.excalidraw"` (the file does not exist, so a new drawing starts from `BLANK_DRAWING`).
- What the plugin writes (`generateMDBase`): `header + "# Excalidraw Data\n\n## Text Elements\n"`, then for every text element `rawText + " ^" + id + "\n\n"`; `## Element Links\n` + `id: link\n\n` for every element with a link (only when there is one); `## Embedded Files\n` + `id: [[path]] {colorMap}\n\n` (or `id: https://...`, or `id: $$latex$$`) only when there are files; then `%%\n## Drawing\n` and the block, closed by `\n```\n%%`. The scene JSON keeps `files: {}`: images live in the vault and are listed only in Embedded Files. On read the plugin finds text anchors with `/\s\^(.{8})[\n]+/` (so ids of 8 characters), element links with `/^(.{8}):\s*(.*)$/`, embedded files with `/([\w\d]*):\s*!?\[\[([^\]]*)]]\s*(\{[^}]*})?\n/`. A drawing with text elements whose Text Elements section is missing or stale is repaired from the scene on the next plugin save, so the section is derived data, not the source of truth.
- In `parsed` mode the scene's text is the display text (a `[[note]]` shows as `note` when `showLinkBrackets` is off) while Text Elements keeps the raw text; the scene's own `rawText` is only a placeholder (`""` on every text element of the largest plugin-written real drawing). Writing the Text Elements section from the scene alone would therefore lose raw wikilinks.
- Excalidraw component. `@excalidraw/excalidraw` is MIT; latest on npm is 0.18.1 (dist-tag `latest`); 46.8 MB unpacked in the registry, of which `dist/prod/fonts` is 13 MB and 12 MB of that is the CJK family Xiaolai. It runs fully offline in a `WKWebView`: it only reaches for the network to load fonts (default base `https://esm.sh/@excalidraw/excalidraw@<version>/dist/prod/`, read from `window.EXCALIDRAW_ASSET_PATH`, which may be a string or an array) and, behind buttons, for libraries and Excalidraw+ links. Self-hosting: set `window.EXCALIDRAW_ASSET_PATH` before the first render and serve `dist/prod/fonts/**` under it. Locales are lazy chunks inside the package (`pt-BR-*.js` exists, `langCode="pt-BR"`), bundled by Vite, nothing to host. Verified at runtime (see app / Drawings).
- JSON Canvas 1.0 (jsoncanvas.org/spec/1.0): top level `nodes[]` and `edges[]` (both optional), nodes in ascending z-order. Node: `id`, `type` (`text`, `file`, `link`, `group`), integer `x`, `y`, `width`, `height`, optional `color` (`"1"`..`"6"` = red, orange, yellow, green, cyan, purple, or `#RRGGBB`). `text`: `text` (Markdown). `file`: `file`, optional `subpath` starting with `#`. `link`: `url`. `group`: optional `label`, `background`, `backgroundStyle` (`cover`, `ratio`, `repeat`). Edge: `id`, `fromNode`, `toNode`, optional `fromSide`/`toSide` (`top`, `right`, `bottom`, `left`), `fromEnd` (default `none`), `toEnd` (default `arrow`), `color`, `label`. The two real canvases hold 24 text nodes and 17 edges (with `label`), are tab-indented with one node per line and no trailing newline.
- Compatibility risks. (1) Wikilinks: element `link` is `[[note]]` (not a URL) and text elements may contain `[[note]]`; Excalidraw does not open them. (2) Embedded markdown notes (`![[note]]`) and LaTeX (`$$...$$`) are image elements whose file entry is not an image; the plugin renders them, Wisp keeps the entry untouched but draws a placeholder. (3) Text transclusion and the plugin's `%%***>>>text element-link:...<<<***%%` marker are plugin features; the scene already holds the resolved text. (4) Frontmatter keys (`excalidraw-export-*`, `excalidraw-link-prefix`, `cssclasses`, user keys) and Excalidraw Automate scripts are not interpreted; keys are preserved verbatim. (5) A text element whose own text contains a heading line such as `## Mudanças` is fatal for any tool that splits the file on headings: in one of the real drawings an agent tool did that and left the tail of the Text Elements section after the closing `%%`; Wisp keeps that tail as the file's trailer and writes the complete section in its place.

## core / Drawings

- `LZString`: decompression stops with a clear error past 25 million UTF-16 units of output (50 MB), a dictionary twice that, or more iterations than the input can encode (`decompressChecked`, surfaced as `ParseError.tooLarge` / `corruptedCompression`). A port of lz-string 1.5.0 `compressToBase64` / `decompressFromBase64` on UTF-16 code units. The output of `compressToBase64("")` is `Q===` like the library. Parity is tested against vectors produced by the JS library and against the 4 compressed real files (recompressing the decompressed scene gives the stored text).
- `JSONValue`: an order-preserving JSON model whose numbers keep their source text (`45.0`, `1e-7`), so a parsed and re-serialized scene is textually the same JSON apart from indentation, which `ExcalidrawFile.indent` remembers (tab for the plugin, one space for the agent-written files). Strings escape U+2028/2029 so a serialized message is always a safe JavaScript literal.
- `ExcalidrawFile`: parses `.excalidraw.md` (both encodings) and plain `.excalidraw`. It keeps the header (frontmatter and any text before `# Excalidraw Data`), the commented-out variant (`%%` before `# Excalidraw Data`), Element Links and Embedded Files entries (multi-line `$$` entries included) and everything after the closing `%%` verbatim. Unknown content between `# Excalidraw Data` and `%%` is kept literally and in place: lines before `## Text Elements`, an unknown heading (and what follows it) after the last text anchor, and non-entry lines inside Element Links and Embedded Files (kept before the entry they precede, or after the last one). Text after the last anchor (a fragment of an element cut by another tool, or an unknown heading) is kept literally as the tail of the Text Elements section; text between two anchors that is not the next element's own text (checked against the scene's `originalText` by line count) is kept before that element; an anchor that is not in the scene (a deleted element) is dropped with its text. A file whose data region has no closing `%%` is written back without one. The Text Elements section is only rewritten where it must change: an `^id` line is written for ids that were already in the section and for new or text-changed elements, never for an id whose `^id` already appears after the drawing (the trailer), so saving without text edits leaves the section byte for byte as it was (all 6 real drawings round-trip identically). Otherwise it is regenerated from the live (not deleted) text elements of the scene, in the order of the existing section and then scene order; an element whose scene text is the one read at load keeps the raw text found in the old section, so `[[wikilinks]]` survive; an edited element is written with its new text. Ids of any length are read; a text element's raw text is the old section's text while its scene `text` is unchanged since load, otherwise the new `originalText` (a stale non-empty `rawText` never wins), and when the edited text still shows the display part of a `[[link]]` (alias, target or file name) the original `[[...]]` markup is put back around it, in order; a link whose text was edited away is written as plain text and `ExcalidrawFile.notices` says so (shown in the toolbar).
- Dead anchor with a blank line in its text (hand edits only): for `line1\n\nline2 ^DEAD` where the scene has no element `DEAD`, the split is ambiguous (the dead element's text may itself contain a blank line, or `line1` may be the user's own paragraph), so `ExcalidrawFile` keeps the paragraphs before the last one as stray text and drops only the last paragraph with the anchor. Keeping never loses user text; the cost is that a multi-paragraph dead element leaves its earlier paragraphs behind. Pinned by `testADeadChunkWithABlankLineKeepsTheEarlierParagraphAsStray`.
- Encoding is preserved: a compressed file stays compressed (256-character lines joined by a blank line), a ```` ```json ```` file stays json. This differs from the plugin, which would convert on its next save; agent-written plain files stay greppable.
- Element Links are rebuilt from the scene's `link` fields plus the old entries whose element has no `link` field. Embedded Files entries are never dropped while the drawing is open (undoing an image deletion reuses the entry, so no second `Pasted Image` is written); `pruneEmbeddedFiles()` removes the ones no live image element references and the model calls it only when the view closes, in a drawing edited in that session. Images pasted in Wisp are written next to the drawing as `Pasted Image YYYYMMDDHHmmss_SSS.<ext>` and listed as `id: [[name]]`, and the scene's `files` is emptied. Elements created in Wisp get 8-character ids from the plugin's alphabet (`1234567890a-zA-Z`, the plugin's `customAlphabet(..., 8)`) because the plugin reads anchors with `/\s\^(.{8})[\n]+/` and element links with `/^(.{8}):\s*(.*)$/`; the long Excalidraw id is aliased consistently across saves and rewritten in `containerId`, `frameId`, `boundElements` and bindings, while ids already in the file are never touched (a test runs the plugin's two regexes over the serialized output). The `appState` of a saved scene is merged over the previous one, because the editor exports only a few keys and the plugin writes 34.
- `AtomicFile.write` is the only writer: it resolves a symlinked file first and refuses a target outside the brain root, writes a temporary file next to the target with the original mode, `fsync`s it, re-reads the target's hash right before `rename` (a difference, or the file having vanished, throws `changedOnDisk`, which the models turn into the conflict banner) and `fsync`s the folder. `NewDrawing.create` refuses a settings `folder` with a `..` segment or a leading `/`, `\` or `~`, removes `/`, `\` and `:` from the prefix, the formatted date and canvas names, and checks the resolved folder (symlinks included) with `DrawingAttachments.confined` before creating or writing. New drawings follow the plugin's settings read from `<brain>/.obsidian/plugins/obsidian-excalidraw-plugin/data.json` (read only): folder, filename prefix, a moment-style date pattern (`YYYY MM DD HH mm ss SSS`, `[literal]`), extension rule, `compress`, `compatibilityMode`; a clash gets `_0`, `_1`... like `getNewUniqueFilepath`. Without the plugin the defaults are the plugin's own (`Excalidraw/Drawing YYYY-MM-DD HH.mm.ss.excalidraw.md`, compressed).
- Plain `.excalidraw` files keep whether they ended with a newline. A file whose text is not lossless in UTF-16/UTF-8 (a lone surrogate escape, invalid UTF-8, an unpaired surrogate inside the compressed data) opens read-only with `readOnlyNotice`, is never written, and the Editar button is disabled; the same for canvases. `DrawingEditSession` holds the edit/flush rules the model drives: leaving Editar asks the page for a last save when it is dirty, and late `changed`/`dirty`/`save` events are accepted while the page is dirty or a save is awaited, not only while editing. `DrawingFileState`: SHA-256 of what is on disk. Clean and different: reload. Dirty and different: prompt. Our own write updates the hash, so it is never seen as external.
- `ExcalidrawSVG`: a lightweight native renderer (rectangle, diamond, ellipse, line, arrow with heads, freedraw, text in lines, image placeholder, dashed/dotted, opacity, rotation, the scene background) for inline embeds. It does not do hachure fills or the hand-drawn look. `DrawingEmbedCache` keys the SVG by the SHA-256 of the file's bytes, in memory and in `~/Library/Caches/ai.wisp.app/drawing-embeds/<hash>.svg`; an empty drawing caches as "nothing to draw". Elements with a non-finite coordinate or one beyond 1e7 are skipped, so a hostile `1e999` or `1e30` never reaches an integer conversion.
- `JSONCanvas`: nodes and edges keep their raw members (unknown keys survive), the top-level key order and the trailing newline; serialized the way Obsidian writes it (tab indent, one compact node per line). The two real canvases come back byte for byte.
- `BrainNewDrawing` (Brain tab, not the plugin-settings `NewDrawing`): `content` is `ExcalidrawFile.blank().serialized()` (plugin header, empty Text Elements, empty compressed scene) or `JSONCanvas.blank().serialized()`, both parsed back and re-serialized byte for byte in tests. `path` names `Desenho|Canvas yyyy-MM-dd HH.mm` + `.excalidraw.md|.canvas` in the chosen folder and appends ` 2`, ` 3`... before the extension while the path exists on disk or in the tree (case-insensitive); the plugin's `_0` suffix and `Excalidraw/` folder are not used. `create` writes through `BrainFiles.createNote`, which refuses an existing file and replaces atomically. `BrainModel.createDrawing` adds the entry to the tree, expands the folder, opens it in a new tab (drawing view) and rescans so search finds it. Entry points: tree header menu, the Brain ... menu (folder of the open note, root when none) and the folder context menu (that folder).
- `DrawingBridgeEvent` / `DrawingBridgeCommand`: the web page posts one JSON string per message to the `wisp` handler (`ready`, `changed`, `save`, `exported`, `openLink`, `failure`, `log`); Swift calls `window.wispBridge.receive(<json>)` (`load`, `setViewMode`, `setTheme`, `requestSave`, `export`). Scenes travel as JSON strings inside the message.
- `DrawingLink`: `[[note|alias#heading]]` (and `![[...]]`) becomes `note(target, heading)`; `http(s)` and `mailto` URLs become `url` (`obsidian://` is ignored, like the canvas rule); anything else (including `javascript:`) is ignored.
- `DrawingAttachments.resolve` (embedded images, canvas file nodes) only returns files inside the brain root (the drawing's folder when no root is given) after standardizing and resolving symlinks, so `../`, absolute paths and symlinks out of the brain are refused; the name-only fallback uses `DrawingNameIndex`, an actor that scans the brain once off the main actor and rescans at most every 30 s on a miss. `DrawingRecovery.recoveryURL` names `<name> (conflito Wisp YYYY-MM-DD HH.mm.ss).<ext>`. `DrawingContentSecurity.resolve` keeps the page server inside the bundled folder (no `..`, no empty or `.` segments).

## app / Drawings

- Build: `scripts/build-excalidraw.sh` runs `npm ci --ignore-scripts` and `vite build` in `app/Web/excalidraw` (React 18.3.1, `@excalidraw/excalidraw` 0.18.1, Vite 8.3.8, all exact, `package-lock.json` with integrity hashes committed) into `app/Resources/Excalidraw` (git-ignored, about 8 MB: 7.9 MB of chunks, most of them Mermaid and locale chunks loaded on demand, and 0.5 MB of fonts without the CJK family). `xcodegen` runs it through `options.preGenCommand` (`--if-missing`: it rebuilds when the lockfile, config or sources are newer than the output), and `scripts/build-release.sh` calls it without `--if-missing` before `xcodegen generate`, so a release always wipes `app/Resources/Excalidraw`, runs `npm ci` from the lockfile and builds again. After the build the script fails if the page's policy names a remote origin or `*`, or if any built file (JS chunks, CSS, HTML) contains an `http(s)://` host that is not on the explicit allowed list in the script (XML namespaces, documentation links, collaboration/share/AI/library/font-fallback endpoints and iframe providers, all blocked at runtime by the policy). It needs `node` and `npm` on the build machine only. `overrides` in `package.json` raise `lodash-es`, `katex` and two `nanoid` copies inside Mermaid's dependency chain so `npm audit` reports 0.
- Runtime: the page is served by a `WKURLSchemeHandler` for `wisp-excalidraw://app/` from the app bundle (module scripts do not load from `file://`). Every response and the page's `<meta>` carry `default-src 'none'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self' data: blob:; worker-src 'self' blob:`, no remote origin, no `unsafe-eval`. The web view uses a non-persistent data store and cancels every navigation that leaves the scheme. Verified outside the app with a throwaway `WKWebView` host (the app was not launched): the page loads, Excalidraw renders with the `pt-BR` interface, `Excalifont` is fetched from the bundled path, a 216-element real scene loads, a drawn rectangle produces a debounced `changed`, and `requestSave`, SVG and PNG export answer. Expected CSP noise in the console: Excalidraw also declares its fonts with the esm.sh URL as a fallback and the browser blocks those requests; the font worker and the `eval` fallback used to subset fonts for SVG export are blocked too, so an exported SVG references fonts by name instead of embedding them.
- Fonts that are not bundled: the CJK family (Xiaolai, 12 MB) is left out; CJK text falls back to a system font.
- `BrainDrawingModel`: view mode by default; "Editar" turns on editing. The page debounces `changed` by 450 ms and only reports real content changes (element versions, background, files), not scrolling or selection; the model then saves after 600 ms of quiet, or at once on Cmd+S and when leaving edit mode or closing the view. Before each write the file on disk is hashed; if it changed outside Wisp the write is held and a banner offers "Recarregar do disco" or "Manter o meu". A 1.5 s poll reloads a clean view when the file changed on disk. Closing never drops edits: when the view closes with unsaved edits and the file changed outside Wisp (or the banner is up) the user's version goes to the recovery copy next to the file and `onNotice` is called (default: an alert); the same for canvases. The page sends `dirty` on the first change or text input and `clean` if nothing changed within 2 s, then the debounced scene, so an external change inside the 450 ms window prompts instead of reloading; closing while the page is dirty asks it for a last scene first. On reload the viewport (scroll and zoom) is kept; only the first load fits the content. Not verified at runtime in the app itself.
- Wikilinks: in view mode a click, in edit mode Cmd/Ctrl+click, on an element whose `link` is a wikilink or whose text contains `[[note]]` (hit test in scene coordinates) posts `openLink`; the link icon calls `onLinkOpen` the same way. The callback `onOpenNote` gets `target` or `target#heading` without brackets or alias; the Brain tab resolves it. Web links open in the default browser.
- Brain tab hosts: `BrainTab` and `BrainReaderView` create `BrainDrawingView` with `vaultRoot` (the brain root) and `onOpenNote`, which calls `BrainModel.openFromDrawing` (splits `target#heading`, then `follow` from the drawing's path) (a missing note shows the usual create prompt).
- `BrainRefactor.plan` never edits drawings (`BrainFileKind.drawing`: `.excalidraw.md`, `.excalidraw`, `.canvas`): they are removed from the rewrite candidates, and the ones that link to the moved item are listed in `BrainMovePlan.drawings` (not part of `isComplete`; the rename dialog shows up to 5 names plus "e mais N"). `BrainFiles.stage` now runs F_FULLFSYNC after `copyAttributes` and `futimens`, just before the rename.
- `BrainDrawingEmbedView(url:)` draws the cached SVG through `NSImage` (CoreSVG), read only; it does not handle `.canvas` embeds.
- Canvas is native SwiftUI (`BrainCanvasView`): pan by drag or two-finger scroll, zoom by pinch or Cmd+scroll or the buttons, "Ajustar", text (light Markdown), file, link and group nodes, bezier edges with arrowheads and labels, colors 1-6 and hex. File nodes open through `onOpenNote` (`file` + `subpath`), image files render, links open in the browser. In edit mode nodes move (a group carries the nodes inside it), resize with the corner handle, new text/note/link/group nodes, "Conectar" (select a node, then the target), delete, double-click edits text. It autosaves like the drawings, with the same disk-change banner.

- Closing and quitting: `BrainDrawingModel.stop()` keeps the model and its host alive (strong captures, cleared in `finishClosing`) until the page's last save lands, at most 3 s. `QuitFlush` (WispCore) is a registry of async flushers: open drawing and canvas models register on start and stay registered until the close has finished (`DrawingClosingTracker`), and a flush that arrives meanwhile waits for it; `AppDelegate.applicationShouldTerminate` returns `.terminateLater` when the registry is not empty, runs `flushAll(timeout: 3 s)` and replies. The Brain tab can register its own `flushForQuit` in the same registry.
